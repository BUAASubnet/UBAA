# ADR 0008：应用服务 Worker 承载遥测、更新检查与公告

日期：2026-11-10
状态：已实施
取代：无。本记录取代[统计开关对照](../protocol/parity/app-service.md)中“不新增网络接收端”的单轮范围限制，该记录的“无可用客户端时不得误报开启”规则继续有效。
被取代：无

## 问题与证据

UBAA 2 去掉了旧版中转服务器，旧版依赖服务器的三项能力因此没有承载者：

- 冻结旧版 `1f4b8f84` 的 `server/.../version/AppVersionService.kt` 提供 `GET /api/v1/app/version?clientVersion=`。它只配置一个下载地址，更新说明从 GitHub Release 代理拉取并缓存。
- 同一提交的 `server/.../announcement/AnnouncementService.kt` 从服务器上的 `announcement.json` 读取公告，同一时间只有一条。客户端的 `AnnouncementReadStore.kt` 在本地记录已读 ID。
- 同一提交的 `server/.../metrics/LoginMetrics.kt` 在登录成功时对学号做哈希，写入 Redis HyperLogLog，按 1h/24h/7d/30d 和 Direct/WebVPN 分别去重计数。学号的取值空间很小，未加密钥的哈希可以被枚举还原。旧版客户端没有遥测。

现项目已有 Dart 侧遥测抽象 `packages/ubaa_platform/lib/src/telemetry.dart`，包括事件和字段白名单、敏感字段屏蔽，生产环境默认使用 Noop。设置页有“匿名产品改进统计”开关，但没有接入任何接收端。[本地诊断](../runbooks/local-diagnostics.md)规定诊断报告只在内存保存、不会自动上传，遥测失败不得影响业务结果。

产品需求由维护者在 2026-11-10 确定：

- 统计上游健康度、崩溃与错误、功能使用、性能，以及跨设备去重后的活跃用户和年级分布；
- 恢复更新检查和公告；
- 服务端部署在 Cloudflare Worker；
- 分发渠道包括 GitHub、Apple App Store 和鸿蒙 AppGallery；
- 当前约 5000 日活，预期上限为数万。

尚未验证：Cloudflare 自定义域名在大陆各运营商网络下的可达率；D1 在目标写入量下的实际延迟；隐私政策文本能否通过各商店审核。

## 决定

### 所有者与边界

- 服务端是本仓库 `services/app_service/` 下的 TypeScript Worker，与客户端合同和 JSON Schema 在同一个仓库维护。
- 客户端由 Rust Core 新增的独立模块 `app_service` 承担，负责同意状态、安装 ID、本地队列、上传、更新与公告请求，以及学号派生标识和年级的计算。
- 该模块不属于 `upstream`，不经过 Direct/WebVPN 路线转换，也不读写学校 Cookie 或会话。它使用独立的 transport 实例，只访问构建时配置的服务地址，并保持 TLS 校验。
- 宿主只通过 facade 和 Bridge 使用这个模块。Dart 侧现有的 `TelemetryClient` 白名单保留为第一道过滤，经 Bridge 把事件交给 Core 入队。
- GUI 和 App 命令模式共用 Core 的同一份 SQLite 状态，因此同意状态、遥测开关、安装 ID 和队列都只有一份。

### 数据与隐私

- **采集与默认值**：首次启动时弹出隐私政策，用户同意后遥测默认开启，设置中可以随时关闭。默认开启只在第一次同意时生效；隐私政策升级后重新同意，或撤回后重新同意，都保留用户原来的开关值。用户在同意之前、政策升级后尚未重新同意、或选择“不同意”进入基础模式时，不请求应用服务（删除请求除外）。基础模式下其余功能照常可用。
- **隐私政策版本**：正文只维护一份，构建时嵌入应用供离线查看。收集项目、目的、接收方、存储地点、保留期或用户权利变化时升版，要求重新同意。错别字和措辞修订不升版，但每次修改正文都必须更新登记的正文摘要，由仓库检查强制，审阅时可见。维护者在 2026-11-10 选择这一规则，不采用“任何改动都升版”。
- **上报内容**：客户端按天聚合计数，不上报原始事件流。错误只上报稳定错误码、分类、路线和至多一项安全源码位置，不上报错误原文、URL、响应片段、课程、成绩、文件名或诊断报告。
- **学号派生标识**：
  - 客户端：`SHA-256("ubaa-telemetry-user-v1:" + 规范化学号)`。学号原文不离开设备。
  - Worker：用只存在 Worker Secret 中的密钥再做一次 `HMAC-SHA256`，然后写库。库里只保存 HMAC 结果。
  - 密钥不轮换。只有在泄露时才更换，代价是去重的连续性从此断开。
- **年级**：客户端从学号解析出类型和入学年份，只上报这两项。本科学号全部为数字，前两位是入学年份。研究生前两位是大写字母，表示类型，第 3、4 位是入学年份。研究生字母的含义在看板里映射，客户端不解释。格式无法识别时报 `unknown`。
- **安装 ID**：随机 UUIDv4，不轮换，不和账号直接关联。用户在应用内删除已上传数据后，客户端生成新的安装 ID。
- **删除**：设置中提供“删除已上传的统计数据”。客户端先在共享状态中标记删除进行中，暂停两个进程的上传。Worker 在同一个 D1 事务中写入墓碑并删除该安装 ID 的全部明细，上报写入都以墓碑不存在为条件，因此删除前已经发出的晚到批次不会重新建立明细。删除不直接修改聚合表：尚未定稿的日表和月表在后续重算中反映删除，已经定稿的聚合表不含任何标识，保留原值。
- **保留期**：活跃明细保留 13 个月；错误、性能和功能明细保留 90 天；删除墓碑保留 30 天；聚合表长期保留。聚合表单独保存跨平台、渠道和版本的整体去重日活与月活，因为分组计数不能相加，明细清理后也无法再重新去重。
- **服务端日志**：Worker 不保存 IP，关闭 Workers Logs 和 Logpush，限流只临时使用 IP。

### 更新检查与公告

- 更新和公告是功能请求，不是遥测。用户关闭遥测后照常可用，但请求不带安装 ID 和用户标识，也不计入统计。基础模式和命令模式都不请求。
- 每个渠道单独配置最新版本、跳转链接和最低可用版本。商店渠道只跳转到对应商店。
- 当前版本低于最低可用版本时：
  - GUI 在首页显示不可关闭的更新横幅；用户主动发起需要访问学校的操作时，弹出更新提示；
  - Core 拒绝所有学校请求，并返回 typed `update_required` 错误；命令模式同样受这个门控约束；
  - 本地日程、缓存查看、数据导出和设置仍然可用。
- 维护者在 2026-11-10 选择“常驻横幅加操作拦截”，不采用启动时的全屏阻断页，以免挡住仍可使用的本地功能。
- 服务不可达时，一律不触发门控。只有成功收到的响应才能设置或解除门控；服务端没有给出判断（`unknown`）时保持原状。
- 客户端忽略启动配置响应中的未知字段和未知枚举值，服务端只能新增可选内容，因此扩展响应后旧客户端仍能识别更新要求。
- 门控只在用户同意的状态下生效。撤回同意后，客户端不再请求启动配置，无法得知最低版本要求是否已经撤销，所以门控随之停用，保证基础模式下学校功能可用。重新同意后立即刷新。门控用来在学校协议失效时防止错误请求，不是强制升级手段，用户可以借撤回同意绕过，这一点已经接受。
- 公告以纯文本 Markdown 文件维护在 `docs/site/announcements/`，用 frontmatter 声明定向条件和展示级别。内容发布入口把它们与渠道配置同步到 Workers KV，只写入与远端不同的内容。网站和 App 用同一份来源。
- 公告可以同时生效多条，分弹窗和首页横幅两级，按平台、渠道、版本范围和起止时间定向。客户端在本地记录已读。

### 生产交付

- 维护者在 2026-11-11 确定启用指定分支的 Worker CD。普通 check 和 CI 检查作业只做本地验证；同一提交的检查全部通过后，生产作业才可在受保护的 GitHub Environment 中取得部署 Token、应用 D1 迁移、部署 Worker 并同步 KV。
- 自定义域名与 `USER_KEY_SECRET` 由维护者在 Cloudflare 控制台首次配置。部署只验证它们，避免 Wrangler 在非交互模式中覆盖域名或 DNS。操作见[部署手册](../runbooks/app-service.md)。

### 存储

Worker 只使用 D1 和 KV，不使用 Analytics Engine。

- D1 存同意后的计数、活跃明细、删除墓碑和聚合表，靠定时任务汇总和清理。汇总窗口覆盖全部仍可接收迟到数据的日期，窗口关闭后才定稿。
- KV 存渠道配置、更新说明和公告。

按当前规模估算，每台设备每天写入几十行，Workers 付费版的写入额度足够。

### 已接受的合规风险

Cloudflare 另有部署在大陆的 [China Network](https://developers.cloudflare.com/china-network/)，由京东云运营，需要企业版单独订阅，并要求 ICP 备案。本方案没有采用它，Worker 和 D1 都运行在境外，所以安装 ID 和学号派生标识的上传属于个人信息出境。部署时须记录 D1 的实际数据位置。《个人信息保护法》第三十九条要求出境前取得单独同意。维护者在 2026-11-10 明确选择维持默认开启，并承担由此产生的风险。缓解措施：

- 隐私政策设出境专章，列明接收方、目的、方式、数据种类、联系方式和行权方式；
- 首启弹窗明确点出数据出境；
- 统计可以随时关闭，已上传数据可以一键删除。

上架国内商店之前，应请专业人士审核隐私政策和同意流程。

## 备选与取舍

- **遥测放在 Dart 侧**：不用改 Bridge，但 GUI 和命令进程之间要另做跨进程文件锁，TLS 与超时策略也要重新实现。Core 已经有经过校验的 HTTP、SQLite 事务和可注入 transport，所以选 Core。代价是要扩展 Bridge 并重新生成，而且这属于跨语言边界改动，需要完整验收。
- **Analytics Engine**：按当前规模基本不会触发采样，但会带来第二套存储和查询方式，日活精确去重仍然离不开 D1。所以全部放 D1，代价是要自己管理表结构、汇总和清理。
- **学号去重只在 Worker 端做 HMAC**：数据库泄露后无法枚举还原，但学号原文要经过 TLS 发到境外。维护者选择让原文不离开设备，再由 Worker 叠加一层 HMAC。代价是传输中的客户端哈希仍可能被枚举。
- **分层同意**（匿名计数默认开启，带标识的数据单独勾选）：合规风险更低，但去重和年级数据会明显减少。维护者没有采用。
- **沿用 ubaa_old 的单条公告和单一下载地址**：实现简单，但不适用于多个商店渠道，也不能定向，所以扩展为多渠道、多条公告和定向。

## 验证与迁移

- 来源对照：这些都不是学校协议，在[来源对照索引](../protocol/parity/app-service.md#应用服务遥测更新与公告-1)中逐列记为“不适用”。ubaa_old 只作为产品行为参考，不能借用它的 URL、字段或哈希方式。
- 合同：行为、接口、字段白名单、同意状态机和表结构见[应用服务合同](../contracts/app-service.md)。实现时另外提交 JSON Schema，并把它纳入合同版本检查。
- 失败条件：
  - 非 `agreed` 状态下发出删除以外的应用服务请求；
  - 关闭遥测后仍在入队或上传；
  - 上传内容出现白名单以外的字段、学号原文或错误原文；
  - 服务不可达时阻断功能；
  - 应用服务请求携带学校 Cookie；
  - 日志或诊断报告中出现学号派生标识。
- 测试：Core 使用可注入 transport 的确定性测试，Worker 使用本地 Workers 运行时测试。应用服务是否可用只由构建期配置决定：非 Release 构建只能访问本机回环地址，CI 环境硬关闭遥测，测试通过可注入 transport 构造客户端，都不访问真实服务。合同第 13 节列出的专门场景必须覆盖，包括政策升级后保持关闭、删除与上传交错、跨日复用会话、月底迟到数据和同日升级。
- 设置页现有的“匿名产品改进统计”文案已经不再准确，实现时改为“产品改进统计”，并据实说明收集范围。现有开关的偏好值在生产环境从未生效，迁移时直接忽略，以新的同意状态为准。
- 回退：移除构建配置中的服务地址后，客户端完全停用应用服务，回到 Noop。服务端数据可以按表清空。
