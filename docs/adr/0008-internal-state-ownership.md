# ADR 0008：应用活动、恢复结果与内部流程状态的所有权

日期：2026-11-09。状态：已实施。承接 [ADR 0007](0007-operation-scopes-and-verification.md)。

## 问题与证据

应用的登录、恢复、路线切换和缓存清理共用一个过渡计数。读取、首页投影和恢复中的 backend 重建分别解释这个计数，调用方需要了解其他操作何时开始与结束。单次恢复还通过全局展示状态传递结果，外层再根据恢复目标修正全局状态。

Agenda 未决操作使用步骤、可空正文、可空发布序号、可空远端对象和登记标志组合表达。清除本地数据后保留发布身份是正常状态，其含义需要同时阅读清理、存储与同步协调代码。Judge 的网络读取、缓存复用和在线扫描分别维护课程与详情游标，推进规则存在多个修改入口。

## 决定

- 应用活动由 `ControllerActivityOwner` 持有。初始化、认证、路线切换、退出、backend 重建、缓存清理和恢复各自取得活动令牌，结束时只释放自身占用。普通操作、读取、本地投影和恢复中重建使用集中定义的占用规则。
- 专用服务恢复使用独立的 `serviceRecovery` 活动，沿用该流程对读取与首页投影的阻塞规则；主会话恢复仍允许本地投影并行。
- 单次会话恢复返回明确的状态与错误结果，由统一入口决定发布到全局会话或目标功能。任务队列继续保留既有串行、合并、重试和交付顺序。
- Agenda 的目录尝试、文件发布、保留正文与仅保留身份、未知回执与已登记回执采用具名内部类型。清理正文、登记和确认通过该状态的操作完成。SQLite 存取边界保持原列及编码，读取既有有效记录的范围保持一致。
- `JudgeScanCursor` 私有持有课程位置和课内阶段。网络读取、缓存复用与在线扫描共用接纳索引、完成详情和跳过课程的转换。详情优先级仍由刷新策略决定，游标只负责稳定重排尚未处理的项。
- 会话与缓存代次、操作归属、取消和显示阶段继续分别表达。`SessionLifecycleOwner`、`ReadScope`、`AcademicTermsOwner`、`ReadScheduler` 和唯一 `WriteCoordinator` 保持现有职责，公开 AppController 仍为单个 ChangeNotifier。

## 取舍

状态在实际拥有规则的对象内集中修改。互斥阶段携带该阶段需要的数据，可以并存的活动分别记录。单个通用枚举不能替代账号、路线、查询和实例归属，因此不合并这些维度，也不引入通用状态机框架。

本地操作协调、同步存储表示和扫描游标分别维护。公开 DTO、学校协议、缓存期限、请求与重试顺序、命令输出和持久格式沿用现有合同。

## 验证与兼容

逐操作来源及适用范围见[内部状态所有权对照](../protocol/parity/core-engineering.md#内部状态所有权)。保持既有生命周期交错、恢复合并、扫描顺序、缓存复用、未决发布和清理后身份保留的行为覆盖；新活动所有者和持久类型转换使用对应的确定性测试。

提交验收遵循[开发命令](../development/commands.md#检查选择与完成条件)的并发与存储范围。内部类型不由 facade 或 Dart 包入口新增导出，SQLite 与 JSON 无版本迁移，FRB 生成输入保持不变。验证命令与结果记入对应提交说明，当前实现见[项目现状](../project/status.md)。
