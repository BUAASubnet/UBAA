# 首页课堂签到交互与结果同步

用户要求点击首页签到直接执行，状态文案清晰，签到成功后移除待办。本轮只改变首页触发方式和已有结果的同步，不修改签到协议，不执行真实课堂签到。

## 实现前来源比较

`just refs` 验证旧版 `1f4b8f8412272b6a423d4ad92b396e3db721e6f3`、buaa-api `a63712fa2ae0a6c8066197063ddee98e3a6b5b81`。旧版 `SigninViewModel.performSignin` 直接提交，成功后重新读取今日课程。`LocalSigninApi` 使用业务 sessionId 头，先 GET 时间戳，再 POST 签到，query 为 courseSchedId/timestamp，表单 id 为业务 userId；成功须满足 STATUS 成功且 result.stuSignStatus=1。今日课程的 signStatus=0 为未签到、1 为已签到。

buaa-api `api/class/opt.rs` 的 checkin 同样读取服务器时间并检查返回状态，但 universal_request 的参数位置、业务身份和登录入口与旧版不同，继续采用现有旧版来源支持的 Core 实现。认证 bootstrap/service、跳转/final URL、会话范围、头与编码、无加密签名、DTO、缓存并发及错误语义逐项沿用 [来源矩阵](../source-parity.md) 的“课堂签到只读查询”和“11D Signin 签到”。不复制旧版遇登录字样重放最终 POST 的行为。

## 修复范围

首页原先在签到按钮不可用时仍让整张卡片导航到详情，缓存未签到状态标为“上次未签到”。固定路线回读只更新功能快照，首页独立快照仍保留旧状态。新增失败反例分别验证点击即提交、连点防重、成功移除指定卡片、失败与未知结果保留、缓存卡片只刷新，以及回读同步首页。

首页点击是本次提交授权，仍经过唯一 WriteCoordinator 的 prepare 和一次 confirm，Core 继续重新核对目标与资格。首页不展示第二个确认页面，其他操作保持原流程。缓存状态显示“状态待更新”，点击刷新状态后才提供签到。提交中禁用重复操作，明确成功移除当天对应待办；失败保留，未知结果提供刷新且不自动重试。已确认成功的本地展示标记只影响当前账号当天的首页卡片，不作为写资格或学校状态。

## 回归迁移

新增首页合成测试验证直接提交、重复点击只发一次、成功仅移除对应卡片并抵抗旧快照重建、失败／未知不自动重试、旧状态只刷新。新增控制器测试先复现固定路线回读期间首页仍为 idle，再验证成功及异常都同步首页。原生首页用例将原“准备并取消签到”替换为专用内存后端的一次合成提交与首页卡片消失，其他待办导航继续验证；真实后端不会被该合成入口调用。功能页原有准备确认测试继续保留。

App 首页导航用例原先等待签到确认页再取消，改为断言原 typed 目标直接提交一次。该旧合成后端拒绝提交并抛异常，因此继续断言未知结果保留待办、不自动重试和阳光提醒开关可用。明确成功的路径由专用内存后端原生测试与 UI 测试覆盖。

## 验证结果

按 `just check-plan` 完成六个受影响包检查：Domain 60、Platform 87、App 676、UI 452、Host 101、官方 Flutter App 78 项测试，共 1454 项通过，静态分析通过。冻结引用、敏感扫描、布局与模块检查通过。范围命令首次因新文件超过目录数量限制停止，合并到既有 shell_write 后恢复；UI 静态分析要求 State 内调用 setState，已调整并从该阶段补跑剩余包。旧 App 用例仍等待取消签到确认页，迁移后 App 全包再次通过。

macOS 明暗主题两项原生合成场景通过，覆盖一次直接提交、首页移除签到卡片和其他待办导航。Debug 构建成功，已用既有隔离配置启动并恢复宽屏首页。当前真实首页没有待签到卡片，本轮没有执行真实签到，也没有声称真实提交验收。未运行 iOS／Android 真机或远程 CI。
