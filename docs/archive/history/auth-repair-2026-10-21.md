# 直连与 WebVPN 登录链修复

日期：2026-10-21。基线 `01fd09b4`。来源与逐操作边界见[实现前对照](../source-parity-auth-2026-10-21.md)。用户明确不处理中转，本轮没有相关配置或界面修改。

## 实际缺陷与修复

UBAA2 的 Reqwest 已关闭自动跳转，主登录已有有界 UC 激活与最终状态校验，问题不等同于 Kotlin 的自动跳转中断。但原跳转解析会原样跟随 HTTP SSO，直连无法携带 Secure Cookie，WebVPN 也会选择 HTTP 上游段。

统一认证与业务跳转的目标解析：相对地址先基于响应地址解析，网关包装还原为上游后，仅将精确 `sso.buaa.edu.cn` 默认 HTTP 端口升级为 HTTPS。其余主机、非默认端口及嵌套 service 查询编码保持；再由各调用方核对原有主机白名单，并按当前运行时路线包装。同时修复已编码网关目标绕过白名单的问题，不增加任何允许主机或放宽 TLS。

另发现教务 `currentUser` 探测仅凭 HTTP 200 判为就绪，测试用空 JSON 或任意 `user` 字段替代成功。按 HAR 已证形状增加最终 homeapp currentUser 地址、字符串 `code="0"` 和 `datas.userId` 非空字符串校验。错误响应按原错误体系返回，不把 HTML、空 JSON 或业务错误当作成功；本科不可用时原有 GSMIS 实际探测流程保留。

未增加指纹请求，未更改密码表单、验证码流程、持久化与修订锁、业务 service、WebVPN 编码常量或路线隔离。未修改 UBAA、冻结引用、其他工作树或本机签名配置。

## 失败反例与保留覆盖

- 完整 UC 票据交换：修改前直连、WebVPN 和业务失败分支三项失败，循环边界已通过；修复后认证套件 32 项通过。矩阵覆盖密码/预登录、原始/网关包装 HTTP Location、一次密码提交、Secure Cookie 作用域、去 ticket 回调、最终 status、service 原始编码及没有指纹请求。
- 地址与白名单：精确 SSO 升级、业务链升级、认证及业务的包装主机/协议绕过均先失败，修复后连接合同 13 项、业务跳转 2 项通过。
- 教务状态：HTTP 200 的 HTML/空 JSON、业务错误、错误数据字段、空用户或错误最终地址均先被错误接受；修复后两项状态矩阵通过，八项教务只读回归通过。
- 原测试的成功响应桩替换为合成 `code/datas/userId` 结构；原课表、考试、缓存、导入、共享锁和路线职责继续保留，没有删除覆盖。

## 真实只读验证

使用本机测试凭据，经标准 `verify-live` 入口通过 stdin 注入，每条路线采用单独临时配置目录并由入口清理；不读取或改写桌面运行中的会话，不输出凭据、Cookie、原始响应和个人资料。每条路线只执行一次登录，不自动重试凭据。

| 路线 | 准备/登录/UC status | 教务学期/教学周/当前课表/今日课表 |
| --- | --- | --- |
| 直连 | 全部通过 | 全部通过 |
| WebVPN | 全部通过 | 全部通过 |

命令为 `just verify-live mode=direct feature=schedule` 和 `just verify-live mode=webvpn feature=schedule`。均沿 Rust 生产传输执行，约 1.9 秒与 2.2 秒完成本次认证及课表只读流程。未调用 `/fingerprint`，未提交选课、签到、预约或其他学校写操作。这些事实不代替其他功能、设备或发布验收。
