# 路由策略合同

本合同供修改路线选择、网关探测、域名回退和路线配置的开发者使用，定义 Direct/WebVPN/Auto 的选择规则与安全诊断字段。

`RoutePolicy` 是宿主可选择的策略（`auto`、`direct` 或 `webvpn`）；`ConnectionMode` 是 Core 内部解析出的路线。普通 CLI 帮助不暴露 `--mode`；隐藏覆盖项仅保留给确定性测试、实时验证和诊断使用。

## 配置

`config.toml` 仅允许所有者读取，不包含账号、密码、Cookie、CAS execution、交互式验证材料、令牌或响应正文：

```toml
schema_version = 1

[route]
default = "auto"

[route.features]
schedule = "auto"
exam = "auto"
grades = "auto"
classroom = "auto"
spoc = "auto"
judge = "auto"
```

未知字段、功能名、非 `1` 版本以及三个注册值之外的路线值都会被拒绝并返回 `invalid_input`。文件缺失时使用 `auto`。

配置加载/保存拒绝符号链接和非普通文件目标。写入使用同目录唯一临时文件并原子替换；Unix 确定性测试覆盖并发写入以及目录/文件的所有者权限。这些是本地安全证据，不代表实时路线可用。

## 网关可达性

可注入的生产探测器测试到 `gw.buaa.edu.cn:80` 的 TCP 连通性：

- 单个 500 ms 总期限覆盖域名解析和每个解析地址的连接尝试；每次尝试只能使用剩余预算。
- 只尝试落在 `10.0.0.0/8` 的 IPv4 地址，其中任一连接成功即为 `Campus`。
- 解析失败、无地址、只解析到其他地址（如代理 fake-ip 的 `198.18.0.0/15`）、拒绝/不可达连接和普通超时均为 `OffCampus`。
- 只有内部探测失败（包括故意注入的诊断失败）才是 `Unknown`。

结果由聚合 Core facade 在当前进程内以 single-flight 方式缓存 3 秒；探测器、时钟和缓存行为均可在测试中注入。CLI 不拥有解析器或缓存。探测器不发送 HTTP/TLS 请求、不读取凭据。

目标、端口和时长来自 `examples/buaa-api/src/utils/net.rs`；单一总预算、`Unknown` 边界和 `10.0.0.0/8` 地址过滤是 UBAA 2 产品约束（见 2026-10-28 决策）。

## Auto 读取回退与写入

- Auto 在校园网使用 Direct；校外按下述名单优先选择 WebVPN，名单外域名首次访问仍使用 Direct。
- 名单外的校外初始 Direct 读取使用 2 秒连接预算，响应预算仍为 30 秒。只有读取遇到网络不可达或超时，才在独立 WebVPN 运行时重试一次。
- 请求开始时判断为校内但 Direct 发生网络错误时，重新探测后决定是否回退，不继续用旧校内观察否决回退。
- SSO、Cookie、业务 Token 和认证状态不跨路线复制。
- 认证、权限、业务拒绝、解析错误及 HTTP 5xx 不触发网络回退。显式 Direct/WebVPN 策略不回退。
- 写入只在发送前选择路线，最终写请求及发送后回读保持已确认路线，不自动重发。

## Auto 登录与会话恢复

- 校外 Auto 登录并发认证 Direct 和 WebVPN。至少一条路线就绪即可进入应用，另一路线的验证码失败不强制弹窗阻塞；功能实际需要未就绪路线时交给共同恢复服务。
- 校园网只认证 Direct。
- 已有会话恢复只核验当前所需路线，其他槽位继续保留。
- 首页连接恢复、回到前台和 Auto 网络变化会撤销旧探测缓存并重新检测；校外准备 WebVPN 会话，校内准备 Direct 会话。
- 保存凭据的自动登录许可继续由共同恢复服务校验，未授权时显示登录入口。
- 换网观察和只读取消不等待业务锁；旧的可取消恢复按网络修订失效，新事件使用最新网络状态。未发送的确认和已发送写入继续遵守原协调边界。

## 换网恢复

宿主直接订阅平台连接事件，保留离线和同类型网络变化，避免 Wi-Fi 切换 Wi-Fi 的事件被类型去重过滤。同一轮重复通知合并到最后一次观察，后来的事件始终可以替换旧观察。返回前台重新检查网络。

- 断网立即取消普通读取并保留页面数据，重新联网后恢复原来的学期、周次与筛选条件。网络状态通过页面提示展示，不因为网络超时退出账号。
- 读取取消进入 Rust Future，释放业务读取占用。网络观察独立运行，缓存失效也不等待探测完成；过时探测结果不进入新缓存。
- Auto 联网变化先撤销 Direct 读取，确认校外后撤销旧 WebVPN 读取；回到校园网允许仍正常执行的 WebVPN 读取结束，新请求优先 Direct。
- 一次换网从收到事件起共有 30 秒预算，覆盖探测、排队、会话恢复与原查询重读。超时结束本次自动恢复，用户可以再次手动重试；新的真实网络事件开始新的预算。
- 登录由共同恢复服务按账号、路线与保存许可合并。验证码、凭据拒绝和缺少许可继续使用人工入口。
- 手动切换先取消普通读取，再保存策略，不额外准备两条登录页。目标路线会话不足时原页面保留，按已有恢复许可处理。
- 最终业务写入和写后固定路线核对不进入网络读取取消范围。发送后不自动重放，结果未知继续保留原核对提示。云盘仅取消普通元数据读取，文件传输和写入使用各自既有控制范围，路线能力仍限制为已验证的 Direct。

## 域名路线偏好

### 校外域名配置

内置名单位于 `crates/ubaa_core/src/facade/routing/domains.rs` 的 `OFF_CAMPUS_WEBVPN_DOMAINS`，只在 Auto 且网关探测为 OffCampus 时生效。命中名单的功能直接选择 WebVPN，不先消耗一次 Direct 超时；目标会话缺失时沿原恢复流程处理。显式 Direct/WebVPN 和校园网内的选择不受名单影响。名单与运行时 24 小时偏好分开，回到校园网不会删除内置配置。

2026-11-13 在用户提供的非校园网环境完成 20 个域名的公开入口和 DNS 检查。HTTPS 校验证书，使用公共 DNS 地址、绑定实际联网网卡并绕过显式代理，未使用账号或会话。结果表示本次环境下的观察，后续网络策略变化时据新的证据更新名单。

| 校外选择 | 域名 | 依据 |
|---|---|---|
| WebVPN | `judge.buaa.edu.cn` | HTTPS 443 连接在 5 秒及 8 秒两次预算内均超时 |
| WebVPN | `iclass.buaa.edu.cn` | 443、8346、8081 三个实际使用端口分别在 5 秒及 8 秒两次预算内均超时 |
| WebVPN | `i.buaa.edu.cn` | 两个公共 DNS 服务均返回 NXDOMAIN，AAAA 查询也无记录 |
| WebVPN | `uc.buaa.edu.cn` | TLS 校验通过后无有效 HTTP 响应；HTTP/2 异常关闭，HTTP/1.1 用户信息入口与根页面均返回空响应 |
| WebVPN | `icw.buaa.edu.cn`、`chaxun.icw.buaa.edu.cn` | 用户明确确认财务必须走 WebVPN。[PR #124](https://github.com/BUAASubnet/UBAA/pull/124) 已记录真实 WebVPN 收入读取通过，并修复网关登录失效后的恢复 |
| Direct 优先 | `byxt.buaa.edu.cn`、`gsmis.buaa.edu.cn`、`booking.lib.buaa.edu.cn`、`bykc.buaa.edu.cn` | 入口返回正常的 SSO 登录跳转 |
| Direct 优先 | `app.buaa.edu.cn`、`spoc.buaa.edu.cn`、`ygdk.buaa.edu.cn`、`cgyy.buaa.edu.cn`、`it.buaa.edu.cn` | 公开入口返回 HTTP 200 |
| Direct 优先 | `zfw.buaa.edu.cn`、`bhpan.buaa.edu.cn` | 返回各自登录入口；云盘继续只使用已支持的 Direct 协议 |
| 原认证流程 | `sso.buaa.edu.cn`、`d.buaa.edu.cn` | SSO 登录页 HTTP 200，WebVPN 网关返回登录跳转，不列入业务域名名单 |
| 网络探测 | `gw.buaa.edu.cn` | 公共 DNS 无 A 记录，符合本次非校园网环境，不作为业务路线配置 |

可达入口的首次响应约为 0.11～0.48 秒，不包含登录和完整业务查询。财务入口的匿名 GET 返回跳转，只能证明入口响应，不能替代携带 Token 的正式 POST 查询。上述检测没有新增真实 WebVPN 业务验收；财务的真实业务依据来自 PR #124，其余功能沿已有协议支持。

### 运行时偏好

`domain_routes.json` 在配置目录保存域名和过期时间，不包含账号、URL 参数或认证材料：

- 只有 Direct 发生网络错误且同域名 WebVPN 读取成功后，才记录 24 小时的 WebVPN 偏好。期限从这次确认开始，后续使用不延长；到期后重新尝试 Direct。
- 校园网探测成功时清除校外偏好。
- 已记录域名的 WebVPN 请求发生网络错误或超时时撤销该域名的临时偏好，后续操作重新选择；当前读取不再回退第二次。校外内置名单仍然有效。
- 保存失败保留当前在线结果。
- 课程、考试和成绩共用教务域名记录，SPOC 与评教共用同域名记录；记录按实际失败主机保存，不能将一次 SSO 故障写成所有业务域名不可达。
- 并行只读实例共享进程内记录，新进程从本机文件加载。

读取需要回退而 WebVPN 尚未就绪时，Core 另在内存记录该域名的恢复需求：

- 主客户端与并行只读实例共享此需求，会话恢复沿 WebVPN 执行，避免重新核验 Direct 后误报恢复成功。
- 成功读取或重新确认校园网后清除对应需求。
- 临时需求不写入持久文件。

## 业务缓存与路线

业务缓存按账号及精确查询共用，记录保留最近成功的实际来源路线。路线切换不拆分或清空课表、作业等业务内容。缓存不能授予写资格，提交目标与句柄仍绑定实际路线。北航云盘继续使用已有 Direct 协议，WebVPN 文件传输能力尚未验证，不把普通网页回退扩展到对象上传和下载。

## 路线诊断元数据

Schema-v7 只读 CLI 成功结果和路线解析后的错误都暴露相同的安全诊断元数据：`routePolicy`、`networkState`、`initialRoute`、`resolvedRoute`、`usedFallback` 和 `feature`。

- 显式 Direct/WebVPN 策略不运行网关探测，因此其 `networkState` 为 `unknown`；这表示“未探测或不确定”，不等于校外。
- 宿主将 facade 返回的不可变诊断直接交给渲染层。Core facade 负责配置加载、探测缓存、路线解析、就绪预检和业务执行；宿主不能重建或覆盖普通路线选择。
- 隐藏显式模式仍是独立的诊断/测试入口。隐藏 SPOC/Judge 诊断命令也调用 facade，只暴露[只读功能合同](readonly-features.md)记录的安全元数据，不把路线所有权转回 CLI。

## 会话槽位

首页本地待办投影复用 App 的路线切换与读取生命周期。路线设置在途时撤销旧投影，收尾后按实际策略重新计算。切换前的签到读取只能恢复只读展示，动作需要切换后的新读取及原在线资格核对，详细规则见 [Bridge v45](flutter-bridge.md#v45首页统一本地投影)。本规则不增加学校请求或改变 Core 的路线选择。

`session.json` schema 版本 2 在一个文件锁和 revision CAS 下保存相互独立的 `direct` 与 `webvpn` 槽位。聚合协调器拥有完整快照和 revision，私有 runtime 只接收路线本地状态。旧版单路线快照只迁移到其记录的 `mode` 槽位；Cookie 不复制到另一槽位。Execution 及其他临时登录状态仅保留在内存中。

普通 `UbaaClient` 聚合 facade 按 Direct、WebVPN 顺序准备并提交，分别使用私有 `AuthWorkflow` 和 Cookie/runtime 状态。第二条路线失败时返回 `partial` `LoginOutcome` 并保留第一槽位。聚合 JSON 只暴露路线状态和稳定错误字段。交互式验证页面返回 `upstream_changed`，不暴露挑战或图片。
