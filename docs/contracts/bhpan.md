# 北航云盘边界合同

本合同供修改北航云盘功能的开发者使用，定义云盘在 Core、公共命令、Bridge 与 GUI 之间的授权、路线、写入、传输和缓存边界。

产品安排见[北航云盘设计](../design/bhpan.md)，逐操作证据见[来源对照](../protocol/parity/bhpan.md)，实际验收结果见[状态页](../project/status.md#功能)。

## 范围与所有权

功能完整覆盖冻结 buaa-api Cloud 的 login 和 25 个公开业务操作：文档库和个人目录、目录与大小、建议名称、文件与目录管理、回收站、分享管理和接收分享、下载地址授权、秒传/普通/分块上传。公开产品接口可以组合这些来源操作，具体签名由对应实施任务确定，须保留每项操作的来源去向。

各层所有权：

- Core 拥有学校认证、云盘认证、路线、Cookie/Token、请求构造、重定向、解析、传输、缓存与写入结果。生产宿主只使用 facade 或专用 typed bridge。
- CLI 负责命令与 human/JSON 输出，App 负责状态和交互，平台层负责文件选择、保存及系统打开。
- 日程同步复用同一云盘 Core，不单独持有凭据、拼接 URL 或实现上传协议。

根目录分类包含个人、共享、部门、群组，只表示可读取的文档库。分享预览权限只表示访问设置。没有来源依据的全文检索、在线编辑、文件版本管理、团队管理、应用内预览和持久断点续传不进入可用能力声明。门户提供的剩余空间指标继续遵守[校园账户来源](../protocol/parity/campus.md)，不据此推导云盘配额接口。

## 对象与授权

文件、目录、文档库、回收站记录、分享配置和传输任务分别使用稳定类型。文件名与展示路径用于呈现，文件身份来自 Core 核实的目标。字节数、时间与对象类型由来源解析，不用名称后缀或负数猜未声明的状态。返回对象应携带实际路线、取得时间和列表范围；未知或缺失信息保留为空或明确状态。

个人授权与分享授权分开建模：

- 个人操作绑定当前账号和实际路线的云盘会话。分享链接能够打开，不证明个人账号已登录。
- 接收分享使用 Core 持有的临时分享授权，作用域绑定该分享与其后代对象。授权过期后返回明确状态，由既定恢复流程重新打开分享，不能静默替换为个人 Token。
- 分享另存同时使用个人目的目录授权和该分享的来源授权。其他写操作只在逐操作来源明确支持的授权类型下开放。
- 批量下载只能组合相同授权上下文的目标。不同分享或个人/分享混合选择须分开处理或拒绝，不能借第一项的 Token 代替其他目标授权。
- 分享密码与 Token 属于秘密材料。用户主动创建或复制的分享链接属于功能输出，仅在明确的分享交互中交付，不进入自动日志或业务诊断。
- 分享历史读取的原提取码只由 Core 在当前客户端内存中保留。更新分享时，`keepPassword=true` 沿用原提取码，`keepPassword=false` 使用新密码；两种设置都不会把提取码放入公开 DTO、缓存、日志或错误。

跨 facade/Bridge 的上下文、待确认操作与传输授权使用不透明句柄。宿主不能从句柄解出或设置个人 Token、分享 Token、签名 URL、对象存储头、OAuth challenge 或原始响应。Core 限定句柄的用途、生命周期和所属 client，拒绝把任意 JSON、URL 或裸 ID 兑换为写权限。

## 账号、路线和代次

操作、读取、缓存投影及传输任务绑定账号、实际路线、会话修订、client 生命周期和请求代次。确认、发送、继续下一阶段和发布结果前均检查绑定仍有效。退出、账号切换、路线策略变化、client 释放或会话被替换后，未发送阶段停止，迟到结果不得进入新账号或新路线的界面和缓存。

Direct 与 WebVPN 的能力分别表达为可用、不可用或待验证，并保留安全原因。云盘 WebVPN 的完整认证、分享、对象存储与下载链路缺少证据，保持待验证。通用 URL 编解码、Direct 成功或另一个功能的 WebVPN 成功不能改写该状态。既定路线内失败不透明回退另一条路线。

认证、刷新和分享上下文复用 UBAA2 现有受保护的会话与代次机制，遵守[连接与会话合同](connection-and-session.md)，不移植来源自有的并发容器。严格 TLS 校验、目标主机/路径检查、Cookie 作用域及日志脱敏是 UBAA2 规则。来源中的证书忽略配置、原始错误和共享 Cookie 简化行为不进入实现。

## 读取与列表完整性

空目录、空分享记录、认证失效、权限拒绝、部分范围和解析失败分别表达。缺失必需数组或字段不能变成成功空结果。列表应保留当前请求范围、已读条目与完整性状态；只有来源和实际读取证明完成时才标记完整。

回收站来源固定读取个人目录前 100 项，没有完整翻页实现。目录、分享历史和文档库列表也没有独立的完整性证明。实现可以显示已取得内容，但不得把部分或未知范围用于“全部删除”、全量替换、完整同步或“没有该文件”的确定结论。后续分页须先证明请求参数、稳定顺序、去重与终止条件，再开放完整扫描。

建议名称、旧列表、缓存或某次权限读取都不能锁定目标，也不能保证下一次写入没有冲突。同名处理按已证明的上游语义返回，不能默认覆盖、自动改名或删除旧文件后重建。

## 单次写入与结果未知

写入沿用现有确认规则：CLI 默认拒绝并要求明确确认，Flutter 使用 typed prepare、一次性确认、单次 commit 和只读核对。Core 在最终发送前检查当前账号、路线、代次、目标与操作类型。确认只授权绑定的操作，不授权另一份目标、自动重试或后续真实操作。

每项写操作区分发送前拒绝、确定业务拒绝、确定成功和 `OutcomeUnknown`。写请求可能到达上游后，超时、断线、响应丢失、无法解析成功结果或生命周期变化均可能留下远端效果。此时停止自动重发，返回不可自动重试的结果，并允许在原授权、原路线、原目标上只读核对。核对失败或证据不足时保留未知，不能以目录出现同名文件升级为成功。

多项操作逐项报告已完成、确定失败、结果未知与尚未执行，不承诺上游具有批量事务。某项结果未知后停止后续写入。永久删除与移入回收站分别确认，分享取消与文件删除分别表达。

上传属于一个用户操作下的多阶段状态机：

| 路径 | 必须区分的阶段 | 结果边界 |
|---|---|---|
| 秒传 | 只读哈希探测、创建提交 | 探测成功不授权自动创建，也不保证创建成功；创建提交按一次写入处理。 |
| 普通上传 | 开始授权、对象存储 PUT、最终登记 | 首条开始请求的明确业务拒绝保留原错误。初始化成功后发生错误或结果不明时保留未知；取得的 docid/U 用于定向只读核对。只有正文完整传输及最终登记均成功才完成。 |
| 分块上传 | 初始化、分块授权、逐块 PUT、提交分块信息、对象存储合并、最终登记 | 块传输、对象合并和文件登记分别核对。保存已知阶段，不因后续失败自动重新初始化或重发块。 |

单次用户确认可以绑定确定的多阶段上传流程，但各阶段均至多发送一次；进入结果未知后不得继续后续写阶段。取消只保证停止尚未发送的阶段和本机工作。来源没有远端回滚、取消上传或断点恢复证据，取消后已经到达服务端的结果仍须如实表达。取消、退出或换账号发生在发送后时不能把未知结果写成“已取消且无远端变化”。

首次创建保持 `ondup=1`。版本 facade 按官方字段区分基版 R 与本次上传的新版本 U：固定版本下载传 R，普通/分片开始和最终登记均传 `editedrev=R`，最终登记的 `rev` 传 U。北航部署的原子比较与首次同名不覆盖尚待验证，`conditional_replace` 保持 `Unverified`，真实自动同步须等待对应能力证据。

## 外部地址、请求头与传输

签名下载地址、对象存储地址与授权头只在 Core 内消费。普通 DTO、CLI JSON、Bridge、异常 source、Debug、日志和缓存均不携带这些材料；宿主只接收传输任务、进度、安全错误及必要收据。分享链接的用户交付遵守前述专用交互。

Direct 对象传输的地址与对象请求头来自本次、同一操作的云盘 API 授权响应。Core 核对当前账号、路线、客户端和传输阶段，检查授权结构、预期方法、数组长度、合法 HTTPS 地址及请求头，然后直接消费原地址。宿主输入、历史缓存和其他操作的授权不能替代本次响应。动态授权提供目标依据，无需预先枚举对象主机。

外部传输使用独立的 Cookie 与授权边界，保持严格 TLS 校验：

- 上传只使用本次响应给出的对象请求头，不附加学校 Cookie、个人 Bearer 或分享 Token。
- 基本下载以 GET 消费当次下载地址，校验成功状态并流式写入本机文件；这是客户端对下载地址的最小消费方式。
- 拒绝对象端重定向、额外认证要求和不支持的授权结构；这些分支须取得同操作、同路线证据后才能扩展，不能自动传播授权或补入个人凭据。

协议依据与取舍见[动态传输授权](../protocol/decision-log.md#2026-11-05北航云盘的动态传输授权)。

上传须校验文件长度与实际内容、分块编号和完整性、每块 HTTP 状态、ETag、合并响应及最终登记。缺字段、非 2xx 带 ETag 或短授权数组均不能继续成功路径。大文件使用有界缓冲，不把全部内容复制进 Dart 状态、通用 DTO 或进度事件。文件在计算摘要或上传期间改变时停止并报告，不能提交与确认时不同的内容。

用户发起的文件下载保存到用户通过平台能力选择的文件。Core 与平台须保护已有目标和半成品：明确处理同名保存、空间不足、中断、权限拒绝和完成后替换。平台不具备文件选择、保存或系统打开能力时返回具体不可用原因。断点下载、Range 恢复、文件摘要或归档解压只有获得各自证据后才能声明支持。

## 缓存与本地文件

云盘目录、属性和其他允许持久化的业务元数据继续遵守[离线缓存与恢复合同](offline-cache-and-recovery.md)，按账号隔离并加密。缓存查询绑定路线、完整范围和取得时间，写后按实际影响失效或刷新。缓存仅提供只读展示，不能恢复写权限、临时分享授权或传输凭据。

分享密码、临时分享 Token、个人业务 Token、签名 URL、对象存储授权头及原始响应不进入业务缓存。是否保存分享记录中的必要公开元数据须由相应 typed 缓存设计明确，不能直接序列化来源模型。

用户选择下载的文件是用户文件，其格式和保存位置由功能与平台能力决定，不按业务缓存自动加密、淘汰或清除，也不能被当成缓存修复对象。私有传输暂存文件须受权限和清理规则保护，不能与用户保存文件或运行验收材料混用。运行日志和验收媒体继续放在被忽略的 `.ubaa_local/` 任务目录。

日程采用明文 SQLite 的决定只适用于独立日程存储。该决定不改变云盘元数据和现有业务缓存的加密规则，也不自动启用云盘同步。

## 错误与验收边界

Core 返回稳定、安全的错误与结果状态，区分个人认证不可用、分享授权不可用、权限拒绝、同名冲突、目标变化、范围不完整、协议变化、本地文件错误、确定业务拒绝及结果未知。具体公开错误码与签名在实施任务中确定，不能将任意上游 message 或响应正文直接投影给宿主。

先用脱敏 Fixture/Mock 固定精确请求、编码、重定向、Token 隔离、非法外部目标、授权数组、分块失败、取消/退出竞争和未知结果不重放的行为。CLI 端到端、Bridge/FFI、平台文件能力和真实原生 smoke 按实际改动验收，检查入口以[开发命令](../development/commands.md#检查选择与完成条件)为准。

真实 Direct 与 WebVPN 分别验收，授权规则详见 [AGENTS 真实账号与验收范围](../../AGENTS.md#真实账号与验收范围)：真实账号认证和读取须具备当前会话的功能与路线授权，每次真实写入须具备具体操作、目标、路线和时间授权。源码、计划、凭据存在、确认按钮与 Mock 成功均不扩大授权。路线不可达、授权不足或协议证据未齐时报告对应阻塞与重跑条件。真实业务结果、确定性测试、设备、远端 CI 和发布证据分别记账。

## 当前 typed 入口

Core 的 `UbaaClient::bhpan_*` 提供登录、文档库与个人根、目录、属性、名称建议、回收站、分享历史与记录、接收分享、分享链接交付，以及 prepare/commit/discard。写意图为 `BhpanWriteIntent`，目标和分享均使用当前客户端签发的句柄。分享历史和创建收据保留完整对象关联，可用于更新；缺少目标关联的单项分享记录只用于查看、链接交付与取消。

`bhpan_prepare_fast_upload` 接收平台选择的文件路径、父目录句柄和 `BhpanTransfer`，只接受个人文档库目标。Core 保存签发句柄的文档库分类与根目录 ID；从 All 文档库入口进入时先用个人根接口核对根目录 ID，无法核实时在哈希探测前返回“秒传只支持个人文档库”。进度与取消不携带文件内容，计算摘要使用 64 KiB 缓冲。秒传检查未匹配时返回明确不可用结果，不自动初始化普通或分片上传。任务丢弃、账号变化或客户端释放后，未发送阶段停止。

`bhpan_prepare_upload` 选择普通或分片上传，超过 100 MiB 使用 20 MiB 分片。公共命令在准备阶段记录本机文件的长度和修改时间，Core 打开实际上传源时核对这份快照。文件在目录或分享查询期间变化时，普通、共享和秒传上传均拒绝继续。

`bhpan_download` 实际消费当次授权并交付单文件或 ZIP。对象传输使用 64 KiB 流块，正文不跨过 Bridge。桌面保存面板确认同名处理，Core 在同目录私有暂存后交付；移动端使用系统授权交付私有暂存文件。

OHOS 将用户选择的本机文档 URI 解析为授权路径，通过独占创建避免覆盖同名目标。远端 URI 返回不可用。交付以 64 KiB 为上限逐块读写，关闭文件后才报告成功。失败时关闭文件，再清理一次本次创建的目标；清理失败时提示残留文件。平台依据见[OHOS 文件交付](../protocol/decision-log.md#2026-11-05ohos-下载文件交付)。

`bhpan_download_preparation` 只请求下载授权并返回脱敏目标摘要。`destination_verified=false` 表示尚未访问或核实对象地址，不可作为内容下载完成的收据。能力字段使用 `Available/Unverified/Unavailable` 分开表达实现与证据状态。

公共命令通过同一个 Core 及 App 材料和恢复服务执行：

- `upload`、`upload-fast` 要求 `--confirm-write`，`download` 要求 `--output`，已有文件另需 `--overwrite`。
- 分享链接格式在打开材料前校验；更新与取消仍使用本次历史读取中唯一匹配的完整链接。
- 指定 `--password-stdin` 时须提供一行非空密码。
- 进度只写 stderr，stdout 保持单份 human/JSON 结果。
- 总期限贯穿材料锁后的各发送边界、对象流块与输出收尾，停止后不重发写入。

`bhpan_lookup_personal_path` 保留 Found/Missing/Unknown 类型；当前读取范围无完整性证明，未找到时返回 Unknown。`bhpan_file_version` 签发绑定本客户端、同对象及非空 R 的快照；`bhpan_download_file_version` 固定 R；`bhpan_prepare_version_upload` 与 `bhpan_commit_upload_version` 返回成功或 unknown，并保留已经取得的 U。版本快照不能跨客户端恢复写权限。

## 公共命令示例

```sh
ubaa bhpan list
ubaa bhpan upload /课程资料 ./实验报告.pdf 实验报告.pdf --confirm-write
ubaa bhpan download /课程资料/实验报告.pdf --output ./实验报告.pdf
ubaa bhpan download /课程资料 /说明.txt --name 备份 --output ./备份.zip
```

上传的三个位置参数依次是云盘父目录、本机文件和云盘文件名。个人秒传使用相同参数，将 `upload` 换成 `upload-fast` 即可。下载参数中，`--name` 设置云盘打包名，`--output` 指定本机保存路径。已有本机文件只有显式指定 `--overwrite` 才能覆盖。
