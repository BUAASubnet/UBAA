# 认证与用户合同

## 概念

GUI 和 App 命令共用账号材料和会话恢复策略，通过 Core facade 登录、注销、核验会话和读取用户资料。Core 持有传输、认证运行时和持久会话；宿主只管理用户确认和平台安全材料。接口以[认证 facade](../../crates/ubaa_core/src/facade/auth.rs)、[交互认证](../../crates/ubaa_core/src/facade/interactive_auth/)和[CLI JSON Schema](cli-json.schema.json)为准。学校请求的依据见[认证与会话对照](../protocol/parity/auth-session.md)。

## 不变量

- **路线各自认证。** Core 独立准备及核验 Direct 和 WebVPN。聚合成功允许部分就绪，保留成功槽位和其资料，只为失败路线返回错误；全部失败不交付身份。仅由显式诊断或测试使用固定路线底层入口。
- **验票与资料分离。** SSO 验证一次性票据才确认学校身份，跳转或落地页成功不能代替验票。WebVPN 另外核验网关会话，UC 按需激活，资料读取失败不直接撤销 SSO 会话。认证跳转由 Core 校验主机、路线和 TLS。在线学业入口按已核实的门户身份分流，不从学号或缓存推断，见[只读功能合同](readonly-features.md)。
- **挑战绑定当前准备。** 普通非交互入口不暴露验证码。支持交互的调用使用同一路线、同一次准备对应的短期挑战，不能跨路线复用或在提交前重取登录页来替换准备状态。静默尝试耗尽后仅交接仍有效的挑战；更换账号、客户端、会话或路线后重新准备。风险确认不自动循环。
- **登录许可与会话所有权独立。** `canRestore` 约束重启和其他进程的恢复；不记住密码仍允许当前控制器使用已核验的本次会话，不允许后台读取密码重新登录。主动退出先撤销共享恢复许可，再按[会话合同](connection-and-session.md)清理。持久冲突不能用外部新版本重试覆盖。
- **稳定输出。** CLI 的成功、部分成功、失败和参数错误使用同一版本化输出约定，版本、状态及退出码以[命令输出实现](../../crates/ubaa_command/src/io/)及 Schema 为准。调用方按结构和稳定码判断，不解析文案。显示资料和遮罩标识不授予认证或写入资格，密码和登录临时状态不得进入正常输出。

## 错误语义

- 未就绪或明确失效时仅恢复所需路线；没有保存许可、凭据遭拒或需要交互时转人工登录。网络超时或上游暂不可用不等于会话失效，不清掉仍有效的账号材料及只读页面。
- 非交互入口遇到不支持的挑战按稳定协议错误返回；交互入口区分验证码错误、挑战失效及密码风险确认错误。仅对仍可提交的挑战继续交互，不能以普通解析错误替代明确的认证拒绝。
- 会话修订冲突废弃当前客户端的旧会话状态，保留其他进程已保存的新快照。调用方重新打开或恢复后才重做只读操作，不借冲突自动重发写入。
