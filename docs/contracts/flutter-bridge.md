# Flutter Bridge 合同

## 概念

Flutter 与 OHOS 宿主通过 FRB 的 typed 接口调用 Rust Core facade。Bridge 投影 Core 的结果、管理不透明句柄和写入确认，不自己实现学校协议。接口、类型及字段以 [Rust Bridge API](../../crates/ubaa_flutter_bridge/src/api/) 和[已生成的 Dart 绑定](../../packages/ubaa_bindings/lib/)为准。学校请求的依据见[协议对照](../protocol/README.md)。

## 不变量

- **版本协商。** Core 导出的版本以 [`client.rs`](../../crates/ubaa_flutter_bridge/src/api/client.rs) 为准，宿主只接受 [`bridge_backend.dart`](../../packages/ubaa_app/lib/src/bridge/bridge_backend.dart) 明确列出的版本。版本不匹配时释放新建资源并停止初始化。原生库与 Dart 绑定按同一生成链交付，不能用放宽版本判断替代重新生成。Bridge 版本与缓存格式和 CLI 输出版本独立。
- **类型和隐私边界。** 宿主只使用 typed DTO 和不透明句柄，不重建路线、解析上游正文或取得 Cookie、会话、Token、签名。不把类型退化为任意 JSON；扫码、交互验证码、短期锁码和主动导出的完整诊断仅从各自专用入口交付，不进入普通 DTO、日志和遥测。诊断的分享范围见[本地诊断手册](../runbooks/local-diagnostics.md)。

<a id="2-生命周期与并发"></a>

- **生命周期和并发。** 同组读串行，独立组可并行；认证恢复、路线切换和学校写入独占相关资源，已排队的独占操作不被新读插队。派生读组绑定账号、路线和会话代次，不提交凭据、不写学校、不竞争持久会话。普通读取可取消并释放占用；换网观察不等待业务锁。释放句柄使 intent 失效，等待中的旧结果不得进入新界面。重建必须重新打开，不能复用旧句柄或覆盖尚未收尾的初始化。
- **恢复和投影。** 只核验目标路线，单次恢复受取消和期限控制；期限约束等待和后续请求资格，不保证同步文件操作立即返回，也不因取消回滚已保存会话。读取保留实际路线和精确查询范围，本地缓存不得授予写资格。首页纯投影复用已取得结果，不能为此重读学校或刷新缓存时间；请求代次变化时撤掉旧签到动作，仅用新鲜在线结果恢复资格。独立日程、业务缓存和网络会话各自拥有生命周期，见[日程合同](agenda.md)和[缓存合同](offline-cache-and-recovery.md)。

<a id="6-写-intent"></a>

- **写意图。** 用户按该操作的确认方式授权后，宿主准备并消费绑定操作、账号、实际路线、客户端与有效期的单次 intent。取消或放弃时释放未消费的 intent，不借释放中断已开始的提交。登录、注销、会话核验、路线切换或释放会废弃旧 intent。提交时由 Core 在线复核资格与规范目标；缓存、显示文本、请求摘要和 UI 自造 ID 都不授予资格。图书馆按所选日的北京时间预约窗口限制座位与地图读取和预约，空座不是开放预约的证据。具体入口以 [Bridge 写入 API](../../crates/ubaa_flutter_bridge/src/api/write/) 和 [Core 写入 facade](../../crates/ubaa_core/src/facade/write/) 为准。
- **单次发送与读回。** 每项最终非幂等请求最多发送一次，发送后不跨路线、不自动重放。确定提交与缓存失效分别报告；回读失败不逆转已确认结果。研讨室预约收据只提供安全定位信息，本次订单列表匹配才可标记已核对；取消须用原路线的本次列表与详情共同核对同一订单。阳光打卡上传失败不发最终提交；批次保持已完成项，明确区分未发送和结果未知。重启后的最小提示仅用于只读核对，不恢复 intent 或凭据。

## 错误语义

<a id="3-错误合同"></a>

- Core 错误码、类别、重试标志和已解析路线经 Bridge 保留，定义以 [Core 错误类型](../../crates/ubaa_core/src/error/mod.rs) 和 [Bridge 类型与映射](../../crates/ubaa_flutter_bridge/src/api/) 为准。宿主按稳定码选文案，不用原始正文，也不把解析失败归为协议变化或自行推导可重试性。未知 Core 码和普通 panic 归为安全的内部错误。
- 会话不足交给所需路线恢复；凭据拒绝或需人工验证交给登录界面。网络、超时与业务不可用可按返回标记刷新只读数据；权限、业务拒绝、解析失败、更新门控分别呈现。业务不可用只用于已确认的业务状态或时段。
- 句柄关闭、缺少确认、确认过期、资源冲突与普通网络失败分开处理。重新准备需要最新在线目标和用户确认。写入结果未知不得自动重试，先在原路线只读核对；发送后的 panic 也按未知结果收尾。尚未逐项明确发送边界的旧提交入口可能保守返回未知，调用方仍应禁止重发。
