# 离线缓存与恢复合同（实施中）

本合同落实 [已接受设计](../design/offline-home-and-background-sync.md)。当前已接入今日课表的本地展示与在线保存、平台安全材料和首帧恢复；其余领域、优先调度和验收仍在实施，不表示全方案完成。

## 版本和所有权

业务缓存数据库 version 1 独立于 Session v2、配置 v1、CLI schema v10。新 Bridge 缓存/恢复出口须同步升级 Bridge、生成绑定和 App 消费方；旧双路线 API 不删除或改义。只有 Core 业务仓库保存业务内容，平台仅保存最小账号索引、本地偏好和安全密钥。App 只持有不可写的内存展示投影。

## 本地身份和代次

本地账号使用随机内部标识；账号正文不得作为数据库文件名或日志键。账号索引包含内部标识、允许恢复标记、代次、密钥引用及安全最小展示资料，不包含密码或 Cookie。明确登录成功后验证真实账号归属才能激活索引；主动退出先持久禁止恢复并推进代次，再发注销请求。清除账号失败必须暴露安全错误，不得宣称成功。

读取携带账号代次、路线代次、精确查询键、单调请求修订；结果发布和事务写入都验证。账号切换、退出、清理缓存后旧任务不能重建被清除内容。相同请求合并，旧修订不能覆盖新修订。单账号只有一个受控仓库写入者；仓库本地锁与网络客户端锁分开。

## 缓存键与数据依据

键字段：内部账号标识、实际来源路线、typed 操作、规范化全部业务条件（学期、周、校园日期、时段、校区、课程/作业/订单 ID、筛选、分页与页大小）、载荷版本。缺省与显式条件只有被既有合同证明等价时才合并；不能以当前 UI 选择补写迟到结果的来源。

响应字段：typed 不可写内容、磁盘/在线来源、取得/最后尝试/最后核实 UTC 时刻、精确覆盖范围、完整度、请求修订、保存状态。时间倒退使新鲜度不可信，不能无限延长缓存。失败不修改取得时刻；磁盘失败不撤销已取得在线结果。

完整成功（包括确实为空）才能替换对应集合。部分分页各自记录代次和页范围，不能混合旧页声称完整；失败保留之前成功内容。日期快照不可跨日冒充今日；学期/周投影要求经过验证的日期范围。

## 不可写投影

不序列化 FeatureSnapshot、WriteIntent、opaque handle、ActionEligibility、prepare 目标或提交材料。缓存只保留稳定展示 ID 与白名单字段；用户打开后须在线重读目标与资格。照片字节、精确定位、门锁密码、原始上游正文及认证材料不进入业务仓库。成功写入按操作影响范围失效；未知结果最小核对线索独立保存，不恢复有效 intent，不自动重发。

## 存储和密钥实施判据

候选为事务式嵌入数据库和认证加密载荷；选型须在锁定工具链上验证本机与可用交叉目标，未运行目标单列。元数据也不得明文泄露账号、查询敏感值或正文。随机数据密钥通过专属平台安全接口取得，与凭据 namespace 分离；缺密钥时仅外壳可用，不回退明文或固定密钥。目录/文件拒绝符号链接越界，使用平台私有路径；容量硬限不能因损坏元数据失效。删除、迁移、损坏隔离、磁盘满采用脱敏故障注入验证。

当前事实：官方五端已接入系统安全存储插件，OHOS 已接入 HUKS 通道；macOS 已通过独立合成 Keychain 运行，OHOS 仅无签名构建通过，其余端原生安全材料运行仍待验证。只在能力探测成功的平台启用持久加密缓存；不可用平台不降级明文，不标六端已完成。

## 恢复与调度

`recover_required_session(feature)` 在 Core 按既有策略解析所需路线，只验证该路线，返回 Routed<AuthStatus>；缺本地会话不访问网络，暂时网络错误不自动提交密码。Bridge 返回后归还共享锁，其他路线尚未核实。授权凭据登录另设明确操作并沿旧 CAS 流程；旧 autoLogin=false 不阻止会话恢复，但禁止自动提交旧密码。

首页外壳绘制后由宿主首帧回调创建或合并恢复任务。当前可见查询与写前/写后读高于首页刷新及历史预取。重认证和 backend 重建必须等待写操作安全终态。后台暂停未发送预取，恢复只合并检查，不无条件销毁 backend。

Judge 分段进度为客户端计划，不是上游游标。批次请求全部收尾、会话冲突完成仲裁后才归还客户端锁；下一批启动前重新校验账号/路线代次。不复制 Cookie 规避锁。旧接口保留完整聚合语义；新接口才能明确部分数据。历史课程和详情必须具有复查时间，顺序未证明不遇旧即停，未知日期和长周期项目保留待核实。

## 验收

完整设计第十一节的 15 场景逐项记录。确定性测试、缓存请求成本、原生合成渲染、Core-live、真实 App、性能测量和发布不相互替代。缓存首屏与全部在线更新时间分开；手机/平板/macOS 各至少 30 次并列设备/构建/数据规模，不用 Debug 单次结果宣称达标。

## 已实施的今日课表边界（P1-B）

Bridge v10 新增独立 `BridgeOfflineCache` 和 `schedule_today_cached`。本地操作放入阻塞任务池，不获取网络客户端锁；在线保存仍使用唯一客户端。UC 核实账号后再请求课表，一次捕获的上海日期同时用于请求和缓存键。在线成功但磁盘保存失败返回独立状态；身份不符在业务请求前停止，并关闭本机投影与缓存回写。此时仍有每次读取前的 UC 核验成本，不能据此声称恢复性能达标。

首页缓存读取与认证同时推进。磁盘结果不能覆盖成功在线结果或当前显式查询；页面退出后迟到结果被代次拒绝。缓存完整空集合也显示原保存时间；跨校园午夜不把昨日条目当今日课程。退出先立即隐藏个人投影，再持久关闭索引和缓存，最后请求学校注销；清除账号还清理缓存并移除密钥，错误单独报告。缓存投影构造时移除所有写动作。

## 希冀最小待办接线（P1-C）

Bridge v11 在同一独立句柄上增加 `read_judge` 与 `judge_assignments_cached`。首页只恢复默认不包含过期项的精确摘要，显式 `includeExpired=true` 单独保存；两个范围不互换。完整在线聚合成功才替换缓存，原聚合必需请求失败则保持之前成功集合。首页展示原保存时间与待核实状态，不恢复学校写资格。

本地首页读取返回可用投影及独立局部错误；一个范围损坏仍继续读其他范围。此步骤尚未改变 Judge 的既有六个月逻辑和全聚合网络成本，不是索引选择性刷新、课程部分成功或共享锁让位的完成证明。P2/P3 继续实现这些边界；SPOC/签到等其他首页来源与领域尚未自动持久化。

## 前后台恢复协调（P2-A）

宿主在 paused/hidden/detached 后返回 resumed 时复用 controller/backend 和当前页面。进行中的恢复合并，不在完成后额外重建；初始化/登录尚未完成的前台事件在可恢复时再处理。原实例明确失效时的重建检测仍待后续接线，不能把所有 resumed 当作失效。

WriteCoordinator 公开是否仍拥有待确认意图或活动，覆盖“已经发布 idle、finally 尚未结束”的窗口。恢复等待完全收尾，后台等待与前台显式唤醒共享任务；退出/销毁取消等待。准备/确认/提交/既定回读未结束时拒绝重建 backend。该保护不自动消费意图，也不触发学校提交。无新学校请求或参数；旧宿主恢复自动密码前也核对当前身份，不能跨账号使用安全凭据。

此阶段尚未加入优先队列、恢复退避、明确 handle 失效自动重建、所需路线优先或 Judge 可让位批次；这些仍是 P2 后续交付项，不能用生命周期合并的测试替代其验收。

## 所需路线恢复（P2-B）

生产恢复使用 Bridge v14（所需路线恢复自 v12 引入）：Core 根据目标功能解析路线并只校验该路线；成功返回已核实身份，不先等待另一条路线，也不再阻塞于重复资料查询。只有明确 authentication_required 且带 Core 目标路线时，App 才向 `login_required_route` 交付获准材料；该出口明确为 caller-pinned，不自行重算 Auto。原 CLI/双路线接口保持原义。

恢复请求按功能合并，已发送检查完成后，用户显式目标可提升已有排队请求；每个目标保存自己的完成状态与安全错误。此队列只调度认证任务，不等同所有业务读取已有抢占能力。显式查询先恢复自己的目标；首页默认刷新与当前显式查询使用独立接收条件和唯一修订，不覆盖页面范围；用户目标已排队时，首页整批预载等待该目标认证完成再发送。

本次运行中密码错误或上游未支持交互阻止继续自动使用旧材料；手动成功并完成材料保存后才解除。跨重启的失败策略、自动退避、其他路线的背景需求调度及完整资料的按需补读仍需后续实施。UC 身份校验不是全部个人资料已经更新的证明；长业务读取分段与实际性能也尚未完成。


## P2-C 分段读取合同

希冀扫描使用现有主运行时，每次保持完整“服务激活/选课→索引或详情→会话仲裁”序列，返回后再由宿主决定下一批。不复制 Cookie、不启动另一个持久会话客户端、不在选课和业务读取之间让位。扫描开始后课程索引、每课程作业索引及逐项详情均可渐进返回；不沿用旧 historical_courses 永久排除集合，不用单个旧项推断后续顺序。当前仍遵守原五分钟列表/两分钟详情内存 TTL，持久选择性刷新和准确新鲜度将在 P3 实施。

本地仓库新增非消费式 `validate_read`，在短事务中核对 account/epoch/revision。扫描在每批请求前后核对该票据及客户端/路线/会话代次；缓存不可用目前会阻止新扫描，尚未实现该入口的无持久存储降级。扫描本身不发布、不覆盖既有摘要，部分失败不会删除旧缓存。长期扫描超过 4096 个其他请求时的票据续租与持久详情发布仍须在 P3 一并处理，不能简单重新 begin 抢回较新请求的资格。

## P3-A Core 持久选择性刷新

`begin_judge_refresh(cache, JudgeRefreshOptions)` 与 `next_judge_refresh` 在 P2-C 的原客户端短批次上增加持久课程/作业索引、详情、摘要和课程复查依据。每批返回实际路线、索引/详情、渐进摘要、是否复用、数据原取得时间和独立保存错误；不是学校写资格。当前详情优先于课程提示，新 ID 或标题/课程名称变化优先于已有活跃项，明确历史项最后。完整刷新绕过本地期限与原内存 TTL；旧聚合/CLI 仍使用原 TTL，新增参数不会发送上游。

当前低频历史判定保守地要求：开始时间确实早于上海日历六个月边界、截止超过十四天且明确全部提交。未完成、状态未知、长周期未截止、缺失或不可解析日期都不进入历史隐藏/低频集合。历史课程索引一天复查，历史详情七天复查；当前详情及完整刷新强制读取，其他活跃详情两分钟内可复用。索引复查状态绑定索引 revision 和原校验时间，课程包含一个旧项不能排除后续项。包含历史只改变摘要筛选，完整刷新才绕过所有本地期限。

父扫描票据与长课程复查票据分别原子续租；每个子请求在发送前取票据，发布时同一事务校验父/子资格。续租不能夺回被新请求替代的资格。成功的索引和详情逐条保存；失败仅更新尝试状态，完整摘要只在覆盖完成后替换，部分失败保留原完整摘要，失败课程的渐进投影恢复旧内容。日期和完整度来自真实读取或原记录，不以本次复用时间改写原新鲜度。

新增 `JudgeCourseReview` 是账号密文库中的 typed 复查依据和紧凑课程摘要；排序只读一次该记录，不逐项解密完整详情；不修改数据库表、旧 CacheQuery/Payload 标签或 schema v1。新查询键不会被旧客户端读取；既有缓存仍能打开。保存异常与学校查询异常分别返回；账号关闭/任务被替代为硬栅栏。新扫描仍需要可用的本地仓库，完全不可用时的在线降级，以及 Bridge/App 消费此新刷新合同尚待接入，不能把 Core 完成当作产品端完成。

实现所有权：`facade/judge_refresh/policy.rs` 管理期限和保守历史判定，`read.rs` 管理单批读取/复用，`history.rs` 管理课程复查依据，`progress.rs` 管理渐进投影和完整替换；跨句柄资格与原子发布仍由 `cache/store.rs` 拥有。`JudgeRefreshBatch.fetched_at` 表示本批内容的来源时间，不能直接赋给混合新旧内容的全量投影；Bridge/App 接线时须携带汇总的最早有效来源时间并与当前同步状态分开。

## P2-D / P3-B App 渐进接线

生产 BridgeBackend 使用可选 ProgressiveReadBackend 合同，把希冀首页摘要和单项详情接入 v14；未具备能力的旧 backend 继续原 typed 合同。控制器以真实 Core 返回的一批作为调度单位，当前签到优先于普通显式查询，显式查询优先于首页和后台后续批次。学期/周次/成绩/首页补充等物理读取也进入同一生产队列，不把复合 Future 整体持锁排队。同参数的在途首页或显式读取合并，账号代次失效取消未发批次并丢弃迟到结果；前后台只暂停/恢复后续普通批次，不声称中止在途 HTTP。

WriteCoordinator 的既定回读使用内部独立优先级，跳过后台认证恢复，避免被自身 pending 状态阻塞；普通队列在写活动/确认/回读、恢复认证和前后台边界暂停。没有增加学校自动 commit 或未知结果重发。不同功能的独立归属和当前查询保护继续保留。

渐进投影在首批后通知界面，后续仍标 loading；未取得详情的索引仅展示真实标题和“详情待更新”，不编造日期、分数或进度。单项详情的准备步骤不替换旧目标内容。部分失败结果可同时携带合法内容和局部错误；DataOrigin.mixed 区分混合来源，迟到磁盘不能覆盖此类进行中结果。完整刷新是希冀按需查询面板中的显式选项；与“包含已过期作业”分别控制读取策略和展示范围。

仍未关闭的边界：无可用本机仓库时沿旧在线聚合降级；希冀显式批量详情仍沿既有批量接口；网络退避/句柄重建及十二领域统一缓存需继续实施。当前接线不代表所有大读取已经可让位，也不代表 P2/P3/P4/P5 全部验收。


## P2-E 逐目标认证与只读计划重建

生产逐批 backend 的认证准备与物理读取共用业务队列，按该领域调用所需路线合同；课表已就绪时先读取，不先等待其他首页领域全部认证。恢复后的读取在同优先级先于尚未开始的其他认证，仍让位紧急任务。学期/周次、成绩、预约用途和首页补充读取同样按各自领域恢复；失败保留该领域的原错误，另一就绪领域仍可读取。旧 backend 保留原聚合认证兼容路径。

只读请求遇到明确 authenticationRequired 最多重新检查/恢复一次；实际登录只使用已获准自动使用的安全材料和 Core 返回的固定路线。渐进计划在实际登录成功且身份核对后，取消同路线或尚未确定路线的旧句柄，保留页面内容与原请求归属，再重新 begin；已知属于另一条路线的计划不受此标记影响。连续认证失败或再次被替换即交付错误，不循环重建。账号不匹配不进入重试，其他网络/业务错误不当作认证失效。该恢复规则不用于 WriteCoordinator 的既定回读，不增加 commit 或未知结果重发。

当前仍有局限：全局恢复状态继续保守影响写入口；这里完成的是各领域只读可用性隔离，尚未宣称所有路线写资格已经独立。没有新增跨重启失败退避或 ClientDisposed 自动重建，也没有新增上游协议或持久存储结构。


## P4-A 精确查询本地恢复

新增可选 `OfflineQueryBackend` 与 `OfflineQueryRead`，与在线读取任务独立。当前生产接入今日课表显式查询、希冀摘要（含过期筛选）和单项详情；不是十二领域全部完成。希冀详情从 Core 已保存的 typed 详情读取，路线/课程/作业必须全部匹配，不创建新网络请求。今日查询继续由 Core 使用上海当前日期，不用今日内容代替带学期和周次的周课表。

固定路线只读该路线，Auto 可选已保存的最新来源并保留实际路线；任一路线损坏不遮蔽另一有效记录，损坏与内容分别返回。缓存查询保留原查询上下文、原取得时间、完整度和只读导航，不恢复操作资格。`fullRefresh` 仍允许先展示同范围旧内容，随后在线完整刷新；不会因该选项隐藏缓存。
