# 离线缓存与恢复合同（实施中）

本合同落实 [已接受设计](../design/offline-home-and-background-sync.md)。已接入首页来源、十二领域下文列明的查询/详情范围与遮罩资料，首帧恢复、分段调度、缓存管理、完整学期覆盖及写后关联失效已有实现。当前剩余为最终逐项审查、异常/生命周期多端验证、真实链路故障定位与性能验收；实现存在不等于全方案验收完成。

## 版本和所有权

业务缓存数据库当前为 version 6（加密请求范围、精确失效及最小待核实提示，v1–v5可事务迁移），独立于 Session v2、配置 v1、CLI schema v10；业务记录和索引保留原v1编码。新 Bridge 缓存/恢复出口须同步升级 Bridge、生成绑定和 App 消费方；旧双路线 API 不删除或改义。只有 Core 业务仓库保存业务内容，平台仅保存最小账号索引、本地偏好和安全密钥。App 只持有不可写的内存展示投影。

## 本地身份和代次

本地账号使用随机内部标识；账号正文不得作为数据库文件名或日志键。账号索引包含内部标识、允许恢复标记、代次、密钥引用及安全最小展示资料，不包含密码或 Cookie。明确登录成功后验证真实账号归属才能激活索引；主动退出先持久禁止恢复并推进代次，再发注销请求。清除账号失败必须暴露安全错误，不得宣称成功。

启动只有读取到允许恢复且身份明确的本机账号，才能进入离线首页；首次无账号、主动退出或账号索引/安全材料读取失败时显示登录页。读取异常在登录页保留安全提示，不清除原材料、不自动读取首页。已确认账号后单独的缓存正文损坏或网络失效，仍按原合同保留离线首页和可用内容。

读取携带账号代次、路线代次、精确查询键、单调请求修订；结果发布和事务写入都验证。账号切换、退出、清理缓存后旧任务不能重建被清除内容。相同请求合并，旧修订不能覆盖新修订。单账号只有一个受控仓库写入者；仓库本地锁与网络客户端锁分开。

## 缓存键与数据依据

键字段：内部账号标识、实际来源路线、typed 操作、规范化全部业务条件（学期、周、校园日期、时段、校区、课程/作业/订单 ID、筛选、分页与页大小）、载荷版本。缺省与显式条件只有被既有合同证明等价时才合并；不能以当前 UI 选择补写迟到结果的来源。

响应字段：typed 不可写内容、磁盘/在线来源、取得/最后尝试/最后核实 UTC 时刻、精确覆盖范围、完整度、请求修订、保存状态。时间倒退使新鲜度不可信，不能无限延长缓存。失败不修改取得时刻；磁盘失败不撤销已取得在线结果。

完整成功（包括确实为空）才能替换对应集合。部分分页各自记录代次和页范围，不能混合旧页声称完整；失败保留之前成功内容。日期快照不可跨日冒充今日；学期/周投影要求经过验证的日期范围。

## 不可写投影

不序列化 FeatureSnapshot、WriteIntent、opaque handle、ActionEligibility、prepare 目标或提交材料。缓存只保留稳定展示 ID 与白名单字段；用户打开后须在线重读目标与资格。照片字节、精确定位、门锁密码、原始上游正文及认证材料不进入业务仓库。成功写入按操作影响范围失效；未知结果最小核对线索独立保存，不恢复有效 intent，不自动重发。

## 存储和密钥实施判据

使用SQLite事务数据库与AES-GCM认证加密载荷；锁定工具链上的确定性和交叉构建证据与原生运行证据分列。元数据也不得明文泄露账号、查询敏感值或正文。随机数据密钥通过专属平台安全接口取得，与凭据 namespace 分离；密钥不可用时不能解密或持久保存缓存；身份和生命周期允许时继续在线只读，不回退明文或固定密钥，本机故障与学校错误分列。目录/文件拒绝符号链接越界，使用平台私有路径；容量硬限不能因损坏元数据失效。删除、迁移、损坏隔离、磁盘满采用脱敏故障注入验证。

当前事实：官方五端已接入系统安全存储插件，OHOS 已接入 HUKS 通道；macOS、iPhone/iPad模拟器已有独立合成安全材料运行证据，iPhone空环境私有目录已有原生运行证据；OHOS仅无签名构建通过，Android/Windows/Linux本轮原生安全材料运行仍待验证。只在能力探测成功的平台启用持久加密缓存；不可用平台不降级明文，不标六端已完成。

## 恢复与调度

`recover_required_session(feature)` 在 Core 按既有策略解析所需路线，只验证该路线，返回 Routed<AuthStatus>；缺本地会话不访问网络，暂时网络错误不自动提交密码。Bridge 返回后归还共享锁，其他路线尚未核实。授权凭据登录另设明确操作并沿旧 CAS 流程；旧 autoLogin=false 不阻止会话恢复，但禁止自动提交旧密码。

首页外壳绘制后由宿主首帧回调创建或合并恢复任务。当前可见查询与写前/写后读高于首页刷新及历史预取。重认证和 backend 重建必须等待写操作安全终态。后台暂停未发送预取，恢复只合并检查，不无条件销毁 backend。

Judge 分段进度为客户端计划，不是上游游标。批次请求全部收尾、会话冲突完成仲裁后才归还客户端锁；下一批启动前重新校验账号/路线代次。不复制 Cookie 规避锁。旧接口保留完整聚合语义；新接口才能明确部分数据。历史课程和详情必须具有复查时间，顺序未证明不遇旧即停，未知日期和长周期项目保留待核实。

## 验收

完整设计第十一节的 15 场景逐项记录。确定性测试、缓存请求成本、原生合成渲染、Core-live、真实 App、性能测量和发布不相互替代。缓存首屏与全部在线更新时间分开；手机/平板/macOS 各至少 30 次并列设备/构建/数据规模，不用 Debug 单次结果宣称达标。

以下按阶段保留合同演进；“尚未接线”等描述仅表示该阶段时点，后续同一能力以较新的接线段落为准。当前完整验收状态见活动合同，不从历史限制推导当前代码缺口。

## 已实施的今日课表边界（P1-B）

Bridge v10 新增独立 `BridgeOfflineCache` 和 `schedule_today_cached`。本地操作放入阻塞任务池，不获取网络客户端锁；在线保存仍使用唯一客户端。UC 核实账号后再请求课表，一次捕获的上海日期同时用于请求和缓存键。在线成功但磁盘保存失败返回独立状态；身份不符在业务请求前停止，并关闭本机投影与缓存回写。此时仍有每次读取前的 UC 核验成本，不能据此声称恢复性能达标。

首页缓存读取与认证同时推进。磁盘结果不能覆盖成功在线结果或当前显式查询；页面退出后迟到结果被代次拒绝。缓存完整空集合也显示原保存时间；跨校园午夜不把昨日条目当今日课程。退出先立即隐藏个人投影，再持久关闭索引和缓存，最后请求学校注销；清除账号还清理缓存并移除密钥，错误单独报告。缓存投影构造时移除所有写动作。

## 希冀最小待办接线（P1-C）

Bridge v11 在同一独立句柄上增加 `read_judge` 与 `judge_assignments_cached`。首页只恢复默认不包含过期项的精确摘要，显式 `includeExpired=true` 单独保存；两个范围不互换。完整在线聚合成功才替换缓存，原聚合必需请求失败则保持之前成功集合。首页展示原保存时间与待核实状态，不恢复学校写资格。

本地首页读取返回可用投影及独立局部错误；一个范围损坏仍继续读其他范围。此步骤尚未改变 Judge 的既有六个月逻辑和全聚合网络成本，不是索引选择性刷新、课程部分成功或共享锁让位的完成证明。P2/P3 继续实现这些边界；SPOC/签到等其他首页来源与领域尚未自动持久化。

## 前后台恢复协调（P2-A）

宿主在 paused/hidden/detached 后首次进入可见的 inactive 或 resumed 时复用 controller/backend 和当前页面。P2-T补齐桌面可见但没有焦点的恢复：此时恢复网络订阅和未发送读取；随后 inactive→resumed 不再重复触发，普通焦点变化也不刷新。进行中的恢复合并，不在完成后额外重建；初始化/登录尚未完成的可见事件在可恢复时再处理。原实例明确失效时的重建已在P2-R接线，不能把所有 resumed 当作失效。

WriteCoordinator 公开是否仍拥有待确认意图或活动，覆盖“已经发布 idle、finally 尚未结束”的窗口。恢复等待完全收尾，后台等待与前台显式唤醒共享任务；退出/销毁取消等待。准备/确认/提交/既定回读未结束时拒绝重建 backend。该保护不自动消费意图，也不触发学校提交。无新学校请求或参数；旧宿主恢复自动密码前也核对当前身份，不能跨账号使用安全凭据。

此早期阶段只证明生命周期合并；优先队列、退避、所需路线与分段读取的后续交付见各专项，明确handle失效的当前实现见P2-R。

## 所需路线恢复（P2-B）

生产恢复使用 Bridge v14（所需路线恢复自 v12 引入）：Core 根据目标功能解析路线并只校验该路线；成功返回已核实身份，不先等待另一条路线，也不再阻塞于重复资料查询。只有明确 authentication_required 且带 Core 目标路线时，App 才向 `login_required_route` 交付获准材料；该出口明确为 caller-pinned，不自行重算 Auto。原 CLI/双路线接口保持原义。

恢复请求按功能合并，已发送检查完成后，用户显式目标可提升已有排队请求；每个目标保存自己的完成状态与安全错误。此队列只调度认证任务，不等同所有业务读取已有抢占能力。显式查询先恢复自己的目标；首页默认刷新与当前显式查询使用独立接收条件和唯一修订，不覆盖页面范围；用户目标已排队时，首页整批预载等待该目标认证完成再发送。

本次运行中密码错误或上游未支持交互阻止继续自动使用旧材料；手动成功并完成材料保存后才解除。跨重启的失败策略、自动退避、其他路线的背景需求调度及完整资料的按需补读仍需后续实施。UC 身份校验不是全部个人资料已经更新的证明；长业务读取分段与实际性能也尚未完成。


## P2-C 分段读取合同

希冀扫描使用现有主运行时，每次保持完整“服务激活/选课→索引或详情→会话仲裁”序列，返回后再由宿主决定下一批。不复制 Cookie、不启动另一个持久会话客户端、不在选课和业务读取之间让位。扫描开始后课程索引、每课程作业索引及逐项详情均可渐进返回；不沿用旧 historical_courses 永久排除集合，不用单个旧项推断后续顺序。当前仍遵守原五分钟列表/两分钟详情内存 TTL，持久选择性刷新和准确新鲜度将在 P3 实施。

本地仓库新增非消费式 `validate_read`，在短事务中核对 account/epoch/revision。扫描在每批请求前后核对该票据及客户端/路线/会话代次；缓存不可用目前会阻止新扫描，尚未实现该入口的无持久存储降级。扫描本身不发布、不覆盖既有摘要，部分失败不会删除旧缓存。长期扫描超过 4096 个其他请求时的票据续租与持久详情发布仍须在 P3 一并处理，不能简单重新 begin 抢回较新请求的资格。

## P3-A Core 持久选择性刷新

`begin_judge_refresh(cache, JudgeRefreshOptions)` 与 `next_judge_refresh` 在 P2-C 的原客户端短批次上增加持久课程/作业索引、详情、摘要和课程复查依据。每批返回实际路线、索引/详情、渐进摘要、是否复用、数据原取得时间和独立保存错误；不是学校写资格。当前详情优先于课程提示，新 ID 或标题/课程名称变化优先于已有活跃项，明确历史项最后。完整刷新绕过本地期限与原内存 TTL；旧聚合/CLI 仍使用原 TTL，新增参数不会发送上游。

当前低频历史判定保守地要求：开始时间确实早于上海日历六个月边界、截止超过十四天且明确全部提交。未完成、状态未知、长周期未截止、缺失或不可解析日期都不进入历史隐藏/低频集合。历史课程索引一天复查，历史详情七天复查；当前详情及完整刷新强制读取，其他活跃详情两分钟内可复用。索引复查状态绑定索引 revision 和原校验时间，课程包含一个旧项不能排除后续项。包含历史只改变摘要筛选，完整刷新才绕过所有本地期限。

父扫描票据与长课程复查票据分别原子续租；每个子请求在发送前取票据，发布时同一事务校验父/子资格。续租不能夺回被新请求替代的资格。成功的索引和详情逐条保存；失败仅更新尝试状态，完整摘要只在覆盖完成后替换，部分失败保留原完整摘要，失败课程的渐进投影恢复旧内容。日期和完整度来自真实读取或原记录，不以本次复用时间改写原新鲜度。

新增 `JudgeCourseReview` 是账号密文库中的 typed 复查依据和紧凑课程摘要；排序只读一次该记录，不逐项解密完整详情；不修改数据库表、旧 CacheQuery/Payload 标签或 schema v1。新查询键不会被旧客户端读取；既有缓存仍能打开。保存异常与学校查询异常分别返回；账号关闭/任务被替代为硬栅栏。新扫描仍需要可用的本地仓库，完全不可用时的在线降级，以及 Bridge/App 消费此新刷新合同尚待接入，不能把 Core 完成当作产品端完成。

实现所有权：`facade/judge_refresh/policy.rs` 管理期限和保守历史判定，`read.rs` 管理单批读取/复用，`history.rs` 管理课程复查依据，`progress.rs` 管理渐进投影和完整替换；跨句柄资格与原子发布仍由 `cache/store.rs` 拥有。`JudgeRefreshBatch.fetched_at` 表示本批内容的来源时间，不能直接赋给混合新旧内容的全量投影；Bridge/App 接线时须携带汇总的最早有效来源时间并与当前同步状态分开。

## P2-D / P3-B App 渐进接线

生产 BridgeBackend 使用可选 ProgressiveReadBackend 合同，把希冀首页摘要和单项详情接入 v14；未具备能力的旧 backend 继续原 typed 合同。控制器以真实 Core 返回的一批作为调度单位，当前签到优先于普通显式查询，显式查询优先于首页和后台后续批次。学期/周次/成绩/首页补充等物理读取也进入同一生产队列，不把复合 Future 整体持锁排队。同参数的在途首页或显式读取合并，账号代次失效取消未发批次并丢弃迟到结果；前后台只暂停/恢复后续普通批次，不声称中止在途 HTTP。

WriteCoordinator 的既定回读使用内部独立优先级，跳过后台认证恢复，避免被自身 pending 状态阻塞；普通队列在写活动/确认/回读、恢复认证和前后台边界暂停。没有增加学校自动 commit 或未知结果重发。不同功能的独立归属和当前查询保护继续保留。

渐进投影在首批后通知界面，后续仍标 loading；未取得详情的索引仅展示真实标题和“详情待更新”，不编造日期、分数或进度。单项详情的准备步骤不替换旧目标内容。部分失败结果可同时携带合法内容和局部错误；DataOrigin.mixed 区分混合来源，迟到磁盘不能覆盖此类进行中结果。完整刷新是希冀按需查询面板中的显式选项；与“包含已过期作业”分别控制读取策略和展示范围。

此阶段的无缓存退路及批量缓存缺口随后由P2-I/J/P、P3-B补齐，句柄重建见P2-R。当前接线仍不代表P2/P3/P4/P5全部验收，最终覆盖以验收索引为准。


## P2-E 逐目标认证与只读计划重建

生产逐批 backend 的认证准备与物理读取共用业务队列，按该领域调用所需路线合同；课表已就绪时先读取，不先等待其他首页领域全部认证。恢复后的读取在同优先级先于尚未开始的其他认证，仍让位紧急任务。学期/周次、成绩、预约用途和首页补充读取同样按各自领域恢复；失败保留该领域的原错误，另一就绪领域仍可读取。旧 backend 保留原聚合认证兼容路径。

只读请求遇到明确 authenticationRequired 最多重新检查/恢复一次；实际登录只使用已获准自动使用的安全材料和 Core 返回的固定路线。渐进计划在实际登录成功且身份核对后，取消同路线或尚未确定路线的旧句柄，保留页面内容与原请求归属，再重新 begin；已知属于另一条路线的计划不受此标记影响。连续认证失败或再次被替换即交付错误，不循环重建。账号不匹配不进入重试，其他网络/业务错误不当作认证失效。该恢复规则不用于 WriteCoordinator 的既定回读，不增加 commit 或未知结果重发。

当前仍有局限：全局恢复状态继续保守影响写入口；这里完成的是各领域只读可用性隔离，尚未宣称所有路线写资格已经独立。没有新增跨重启失败退避或 ClientDisposed 自动重建，也没有新增上游协议或持久存储结构。

## P4-S 用量、清理句柄与控制记录升级

CacheUsage只含条目数、业务密文字节、数据库文件页字节、可复用页字节及软硬内容限额。用量不解密业务正文，损坏业务行也可统计其实际占用；已退出或旧代次不返回账号统计。文件页开销与内容限额分列，不把条目正文长度冒称整个文件大小。

OfflineCache.clear_and_reopen保持活动账号的登录入口状态，在一个事务内清空entries/requests并推进epoch及持久generation。事务提交后旧句柄的共享槽置空，新句柄独占接管原仓库连接，不复制Cookie、会话或数据密钥。旧clone永久返回Superseded；独立连接也在同一SQL事务内检查generation，不能新取票、续租、写回、激活或清除新代次。已有clear/deactivate/activate接口保持原用途，设置入口必须使用新合同。已退出账号不允许通过此入口重新开放。

清除事务失败回滚数据和控制状态，原句柄继续可用。事务成功后尽力VACUUM回收文件页；CacheClearReport.compacted、usage和maintenance_error分开报告，不把维护失败伪装成事务未提交，也不隐瞒未回收空间。报告存在意味着内容清除已提交，但不能用缺失的usage猜测当前用量。

数据库v1正确密钥迁移到v2时只重封控制记录、推进旧票据epoch并更新user_version，条目/索引/取得时间不改。v2控制记录使用独立AAD，已打开的旧格式连接也无法解密并覆写该控制记录；错误密钥、未知版本和迁移事务失败均不清空数据。迁移保留原active状态，不能使已退出账号恢复。

所有缓存读取入口先拒绝已确认的Inactive/Superseded，避免旧句柄再发学校请求；普通存储故障继续原在线读取并在保存结果中报告失败。认证过程中发生清理时，后续取票同样拒绝。宿主跨Bridge多步读取仍必须保留启动句柄/代次，不能在旧任务中重新取得清理后的新句柄；App队列取消和内存展示失效在下一接线阶段实施。当前Core能力不等于设置页、保留优先级或损坏到无法打开时的重建流程已完成。


### 缓存管理的 Bridge/App 代际边界（P4-T）

Bridge v25 增加纯本地 `usage` 和 `clearAndReopen`，返回六个数值及新 opaque 句柄；不取学校客户端锁，不返回业务正文。内容清除已提交与提交后的空间维护失败分列。旧 Bridge 方法语义保留，缓存 schema 仍为 v2。

App `CacheManagementBackend` 的管理请求必须带确认时的本机账号标识。清理前检查当前及排队目标账号，进入本地串行通道后再次检查；成功立即替换句柄，事务失败保留旧句柄。请求入队时递增宿主代际，普通缓存读根调用通过 Zone 继承同一代际，每次取得句柄前及最终交付前核对；旧多步调用不能在第二步借用新句柄，迟到的成功与错误均转为操作冲突。此处不是取消已发送 HTTP 请求，也不是业务读取抢占；实际旧写回仍由 Core 事务栅栏阻止。原调用者固定路线写后回读不进入此范围。

账号切换在入队时发布目标账号；首次开启缓存不无故失效已启动的首页读取。退出与清除账号同时失效宿主代际，序列中的退出作用于清理后的继任句柄。控制器的队列暂停、内存清理、页面位置保留及设置入口仍需后续接入，当前 backend 合同不代表完整清理产品验收。


### 设置中的仅清理缓存（P4-U）

现有设置页提供本机缓存用量及确认清理，不增加导航入口。共享数值报告位于Domain，UI不依赖Bridge或App实现。宿主把确认时账号传给控制器，控制器核对当前归属、登录恢复、写活动及待确认意图；写意图存在时拒绝清理，不取消或提交它。用量读取只检查本地账号和清理状态，不等待认证。

清理先关闭新读取/写准备入口，取消延后的恢复，等待既有本地开启完成，再失效旧读取生命周期并取消旧批次。成功删除内存业务投影、辅助读取缓存和资料展示副本，保留认证身份、会话、安全账号材料与当前查询上下文；不自动启动首页同步。失败保留旧数据，并把已取消的loading恢复为stale或idle，允许用户重试。成功与提交后空间回收失败分别提示，失败不能显示成功。

独立businessCacheEpoch通知已访问页面清除展示内容，导航帧及查询参数保留；旧父页内容不能返回复活。选项、领域内部结果与过期选择同步失效。确定性用例证明课表父/子页和未应用学期草稿保留；其他复杂领域表单仍须纳入完整多端验收，不将该用例扩大为全部领域UI验收。


### 容量压力下的保留与入库（P4-V）

仅在预计密文载荷超过软上限时计算保留等级。按损坏条目、已证实过期、普通详情/资源/分页、近90天记录、稳定学业与索引、活跃任务的顺序淘汰；同级按访问时间，未来访问时间按当前时刻截断。低于软上限不逐行解密扫描。扫描时逐行解密并只暂存键/大小/等级/访问时间，业务日期不另加明文索引。现有priority列保留旧格式兼容值，实际策略以store::retention为唯一实现。

课表/考试的当前学期只采用同账号同路线24小时内新鲜、唯一selected的学期元数据；索引缺失不猜第一项。未来考试日期、当日签到/今日课表、截止未到的作业、当日或未来的本人订单优先保留。截止恰好90天仍属近90天，超过才降级；日级订单按校园日末判断。不解释取消/审批状态数字，不把日期保护当作写资格。未知或非规范日期不标过期；详情仍可按普通LRU淘汰，课程/作业索引及复查依据独立保护，以便以后重新发现和读取。时钟倒退不作过期判断。

新密文先在同一事务内预算和回收，再执行INSERT/替换，避免先触碰SQLite页数上限而无法利用可回收空间。计算替换时扣除同键原值；即将成功提交的学期索引参与本次判断，避免旧索引锁死旧课表。软上限可为近90天/稳定/活跃条目留出余量，硬上限不可突破；若新条目只能挤掉更高等级内容才能入库，返回Capacity并回滚全部淘汰。该失败继续经原save_error/savedForOffline反馈，在线数据不因此伪装为已保存。

缓存schema仍为v2，业务编码/索引、Bridge v25和CLI v10均不变。此项不是完整学期导入、损坏文件重建或实际设备性能验收。


### 数据库重建与身份栅栏（P4-W）

控制记录v3增加随机数据库身份并采用独立AAD；读取票据同时绑定身份，重建后即使epoch/revision重复，也不能接纳旧票据。正确密钥下，v1/v2迁移保留业务密文、取得时间和退出状态；持写事务后再次读取版本，避免并发迁移使用过期版本。单行损坏仍只隔离该行。

普通open报错不触发清空。设置确认后从保险箱重新取得临时密钥，调用明确facade/Bridge v26入口；可打开库沿原事务清理，损坏或不兼容库才使用SQLite RESET_DATABASE/VACUUM。独占连接在新控制初始化完成前不释放，避免其他连接看到中间空库。操作仅限当前账号business-cache文件，不处理会话、凭据或其他账号。

清空前失败返回错误；已清空但初始化失败返回空句柄及维护错误，控制器清除内存投影并保留登录/保存失败提示。密钥暂不可用时不重建、不降级明文。调用方只有明确确认后才可走该入口，不能据Corrupt错误断言一定是文件损坏或自动丢弃旧密文。


### 跨学期成绩统计渐进交付（P4-X）

App loadAllGrades可经onProgress交付本地集合，Future继续报告在线结束；UI在刷新期间仍显示保存的统计，不把加载提示替换掉数值。学期索引与逐学期evidence各自保留原时间/完整度，缺项或部分索引不视为完整。最终失败保留同范围历史并明确错误，成功在线结果不被迟到磁盘覆盖；退出/清理/账号路线代次变化拒绝交付。该回调不改变Bridge v26或CLI接口，不将历史成绩送入出分提醒。


### 完整学期导入集合（P4-Y Core基础）

ImportedSchedules按账号和实际路线保存完整导入集合，各学期独立保留terms/termCode/weeks/schedules/fetchedAt。发布前核对完整周次、学期归属和规范化日期；同一次集合原子替换保留其他学期的原内容和时间。普通逐周缓存不进入集合，明确导入内容不参加自动容量淘汰，容量不足返回Capacity，显式清理仍有效。

导入投影支持精确学期教学周、周课表和已覆盖日期的今日列表，不修改原常规读取。未覆盖日期或课程weekday未知返回未保存；覆盖内真实空周可以返回空。跨学期覆盖沿旧版选择开学更晚的已导入学期。Schema v4阻止旧二进制把新载荷误删为损坏，v3迁移轮换仓库代次使旧已打开句柄失效，原条目与时间不变。该Core基础尚不代表生产分段导入或App入口已完成。


### 分段导入与取得依据（P4-Z Core）

新增begin_schedule_import/next_schedule_import及取消句柄，明确请求学期，按学期索引、周次索引、单周分别返回。每批使用同一原客户端真实路线并完成原会话收尾；计划绑定弱引用、会话清理代次、路线配置代次及精确学期租约。全部周成功后才原子发布完整导入；途中失败/取消不自动重发。finished还需结合save_error判断是否已保存。

ScheduleImport{term}只存读取租约，不承载业务数据；最终合并ImportedSchedules时同事务核对父票据。导入集合可选保存周次索引和单周的（实际取得时间、数据库请求修订），按精确修订仲裁常规缓存与导入投影，避免时钟回退或较晚导入收尾遮蔽新结果。旧记录缺该观察时保留原完整导入时间、以修订0作为保守退路。包裹结构仍schema v4，既有条目兼容；Bridge新入口另行升级。

### 整学期任务及可见进度（P4-AA）

Bridge v27逐批暴露Core导入，宿主必须将各批交给原读取调度器；计划不持网络会话副本。App按固定学期合并任务，首页刷新和页面查询不改变任务目标；账号/路线/清理/退出失效取消并隐藏旧状态。在途取消不能假称HTTP未发送，但其返回不得显示保存成功。全部读取与已保存分列，容量错误可显式重试，普通失败不自动重发计划。课表页仅对有本机账号且支持该合同的backend提供保存入口，不恢复学校写资格。

### 离线索引和当前周（P4-AB）

完整导入可以提供学期索引退路，学期索引独立保存取得时间与精确请求修订，较新的普通索引优先。普通周次缓存及导入周次均按校园UTC+8日期重算当前周，不改变原fetchedAt；未知日期、错学期、非正周次及超过七天范围不产生当前周标记。

UI仅对完整persisted索引允许在loading/stale时推进既有只读选择顺序；网络恢复挂起或失败不妨碍打开本地课表，部分索引不自动选择。既有用户草稿、当前查询与路线来源保持原归属约束。


### 关联缓存与在途读取的原子失效（P4-AC Core）

新增CacheInvalidation/CacheInvalidationReport及仓库/facade本地出口。同一短事务按实际路线和影响范围删除条目与在途请求，包含尚无旧条目的请求；随后新读取仍可申请票据。其他账号、另一实际路线和无关查询的票据继续有效，不轮换全库代次或清空全部业务数据。无效范围、损坏请求范围密文或事务错误会整体回滚；本地失效失败不得改称学校提交失败。

requests增加单独AAD保护的加密查询范围，字段不含业务正文、Cookie、密码、写意图或定位照片。schema v5迁移原样保留业务条目密文、时间及退出状态，丢弃旧在途票据并轮换仓库代次，旧已打开句柄也拒绝继续写入。此Core基础尚未接入生产学校写提交，Bridge/App接线与脱敏写流程验收继续；不将本地删除当作学校成功证据。

失效扫描只投影条目的scope元数据，不构造业务DTO；无法解密的旧条目仍由原单条读取隔离，不阻断其他合法目标。读取票据每次验证、续租和发布都验证新增范围密文及其与原票据的一致性，不能等写后失效时才发现损坏请求。

### P4-AE 阳光概览周期

概览按实际路线、分类、已观察学期及校园日历观察周分离；未知学期为独立部分范围。周索引仅定位已经保存的内容，读取返回业务原取得时间。此本地分桶不表示学校教学周或统计清零边界；不推断学校参数。跨日/跨月读取不展示不属于当前日/月的计数。跨周只读当前周索引，旧周仍可保留至容量策略清理。旧单例不推断学期/周期归属。组合请求跨校园日期不发布，较新父任务与关联写后失效都可撤销在途保存。Bridge v28和schema v5保持。

### P2-H 前台退避与网络变化

临时恢复错误的前台自动检查间隔为30秒、60秒，之后至多每5分钟一次；成功、需登录或非临时故障停止该目标退避。后台不发未开始检查，前台和用户重试仍合并同目标任务。网络接口变化只是触发器，30秒内提示合并，不能代替学校认证或直接提交密码。恢复成功后重读仍匹配的失败查询，保留用户学期、参数和导航；退出、销毁、账号代次以及原写流程栅栏持续有效。网络观察不支持时保留计时退避和既有恢复入口。

### P2-I 无持久缓存在线计划

facade的begin_judge_online/next_judge_online不依赖缓存密钥，按完整选课+索引/详情步骤返回，沿原路线与会话所有权和取消栅栏。可选期望账号仍需核对；可选keys为空时拒绝、重复目标去重且只读已核实索引中的目标。新计划强制网络读取，分别报告渐进内容、最早来源时间、finished/complete/失败课程数；这些不是持久保存成功证明。普通失败继续其他课程，认证冲突终止；没有永久历史排除或无证据早停。本段末尾的“Bridge/App接线尚未完成”是P2-I实施阶段记录，已由紧随其后的P2-J接线段落覆盖，当前接线以P2-J及后续状态为准，旧合同保持。

### P2-J 无缓存分段生产入口

Bridge v29与App接入P2-I在线计划。无缓存摘要/单详情及显式批量逐批返回，不绕过原共享锁和写意图保护。控制器通过账号范围入口传递本机身份，覆盖密钥不可读且没有缓存句柄的情况；每次返回同时检查账号/清理代次。批量详情按输入顺序投影，已到合法内容可先显示，局部故障不能宣称完整；当前批量在线计划不保存持久详情，savedForOffline保持false。旧持久摘要/单详情刷新、CLI及双路线接口不变。

P4-AD已经接入学校单次提交后的关联失效：结果与本地缓存故障分列，成功/未知或部分评教已变更后撤销关联条目/请求及内存写动作，再由原只读调度器补刷新。此前P4-AC章节的“尚未接线”为该历史阶段状态，当前以本段和Bridge v29为准。

## SPOC 学期与分页分段合同

`begin_spoc_scan(cache?, expected_identity?)` 只恢复所需路线并确认身份；`next_spoc_scan` 分别推进已观察当前学期、课程补充、全局作业一页。每次包含原业务认证重试及主会话仲裁的完整收尾。计划不持 Cookie 或业务 token，绑定原客户端弱标识、实际路线及主会话/路线代次；取消、退出、较新选择票据或清理拒绝迟到发布。缺本地仓库时仍按可选本机身份核对，不能绕过身份冲突。原 CLI 全量接口不变。

缓存查询新增 `SpocSelection`、`SpocTerm { term }`、`SpocPage { term, page, size:15 }`，沿 schema v5 的加密范围与数据库结构，无明文降级。旧无学期 `SpocAssignments` 记录不推断为当前选择；保留文件内容供原精确查询兼容。首页通过最后有效选择指针读取学期聚合，展示时保留来源学期和原取得时间。新学期部分失败不把旧集合改名成新学期；完整成功才切换完整指针。页缓存独立保存，不从历史残页拼出完整集合。

新观察路径检查明确回显的 pageNum/pageSize 及行 xnxq，错配为 UpstreamChanged；缺分页元数据记部分，不借 DTO 默认值判定完整。保留原 hasNextPage/pages/空页停止边界；自相矛盾、重复作业 ID 或后续空页不能清空旧完整集合。学校失败终止当前计划，不跳页。取得时间从当前学期成功观察开始，不能在最后一页将旧首批数据刷新成新时间。`finished`、`complete`、`publication` 与 `save_error` 分别说明遍历结束、覆盖完整、本次保存与本地故障；前两步 completed_pages=0，宿主应保留原内容而非发布空集合。无缓存扫描 publication 为空，不宣称可离线。

单详情新增 `begin_spoc_detail_scan(cache?, expected_identity?, assignment_id)` / `next_spoc_detail_scan`：前置复用上述分段列表，详情自身有从开始登记的独立 `SpocDetail { assignment_id }` 票据。前置结束时仍返回无详情批次；下一批只读取该已核实目标的必需正文和可选提交状态。列表不完整或可选补充失败时保留旧完整详情；缺目标不请求正文。取消、同目标较新请求、退出/清理在列表完成后仍有效，迟到正文不能入库。没有新学期/课程查询参数；详情 ID 合同沿已冻结上游。取得时间保留列表前置最早观察，不能把较早的课程/状态补充标成最终请求时间。宿主前置阶段保持原详情页面，直到合法同 ID 结果返回。

评教显示读取新增 `begin_evaluation_scan(cache?, expected_identity?)` / `next_evaluation_scan`：固定当前任务第1页/每页10，不新增学期/历史或更多页推断。完整激活、任务、单任务问卷、单问卷课程是让位边界，始终复用原实际路线 runtime。恢复会话时从本次已核实资料按学校标识优先、用户名回退补齐易失账号上下文；两者均缺不发业务请求。计划丢弃内部题目/评价人 authority，完整前与部分结果不返回提交目标，最终仍检查重复身份；缓存只含原显示字段。

新评教批次同时给出已读课程列表数量、完成/完整/保存和可选学校错误。非认证子请求失败保留已读行及首个稳定错误，认证或生命周期失败终止；保存错误独立。中间批次不覆盖旧完整缓存，只读显示可追加新不透明 ID；完整后才替换。旧 CLI/缓存聚合 DTO 及唯一 WriteCoordinator 的 strict fresh 写资格、prepare/确认/单次 commit/既定回读保持原事务，不使用新只读计划代替。


业务只读退避独立于认证退避：完整尝试终止后，仅稳定网络/超时/暂不可用错误且retryable允许时安排30秒、60秒、5分钟封顶；中间批次、取消和写后回读不登记。默认首页与显式精确查询各自绑定账号生命周期和请求修订，成功或新查询撤销旧计时。所需路线就绪按领域检查，另一领域失败不全局阻断。后台、写操作待定、认证进行中、清理或重建时暂停，网络变化合并唤醒；不自动提交密码或学校写入。


## P2-P：希冀存储故障回退

Bridge v33 在既有安全错误上增加可选本地故障分类。持久计划的创建/推进只在明确可降级存储错误时取消旧计划，并让出调度器后启动同客户端在线分段读取。账号不符、清理/退出代次、取消、无效查询及学校错误不能触发回退。保存失败与学校读取状态分别投影到 `DataEvidence.cacheFailure`；首页及详情原位提示当前内容未保存，仍可在线查看。旧内容在不发布的切换批次中保留。


## P2-Q：部分批次的展示范围

希冀在线分段缺少持久内容时，仍按同账号、同实际路线、同精确查询保留已显示的稳定ID和原取得依据；占位不降低已有详情。完整成功集合才替换范围；部分或失败不能据缺项判删除。混合展示剥离动作、标未完成且未保存，不跨路线或账号合并。


## P3-B：明确批量详情缓存

希冀批量详情在线读取逐项保存原完整详情，复用同一课程索引与现有选课安全批次，未成功项保持旧完整记录和原取得时间。批量任务不保存摘要集合，避免子集覆盖整个首页。开始时为所有明确键分配独立票据，存储、取消及清理边界在每个批次前后复核；完整在线内容与保存失败分别报告。离线批量仅使用同路线目标，缺失/损坏不使其余缓存失效，完整度按全部请求键判断。


### 明确失效客户端的原位恢复（P2-R）

仅Bridge已有typed clientDisposed保留为App独立标志，通用internalError、网络或缓存故障不推断为句柄失效。前台合并恢复遇到该错误，且写流程完全收尾后，一轮最多替换一次backend；旧实例释放后才启用继任实例，既有会话由原Core加载，不复制Cookie或恢复写意图。工厂失败、再次失效及网络失败原位提示，保留缓存内容、取得时间和查询上下文。

替换开始与实际接管分别撤销旧读取代次；释放期间新发起的精确查询也转交新实例，旧结果无权发布。仅仍与当前页面匹配的查询重新排入队列。旧动作、资格及内存读取复用失效，页面保持只读；新实例按原恢复协议核对身份，串号则关闭旧账号投影。后台不新建实例，退出或controller销毁发生在释放期间时，只释放继任实例，不打开缓存或恢复会话。本段记录P2-R阶段的Bridge v34，不改学校协议或持久schema；后续P4-AG等阶段已将Bridge推进到v36，当前版本以活动状态页为准。2026-09-24补充的已展示首页显式重建边界会在缓存重开后沿既有`recoverSession`重新核对继任会话，不产生新的学校请求语义，也不恢复写资格。


## P4-AG：未知结果的重启核对线索

显式单次提交前在同账号加密库保存随机本地id、操作枚举、固定路线和开始时间；仅本轮确定结果可自动移除，未知结果和崩溃遗留保留，最多64条且不受普通缓存淘汰。条目绑定账号及id的AAD，不保存学校目标、意图、请求摘要或提交材料。旧库迁移保留内容原时间和退出状态，轮换代次拒绝旧句柄。

首页独立加载提示，不等认证完成；较早读取不能覆盖提交后的新提示。查看相关功能不自动断言结果，用户可在核对后移除本机提示。退出、账号切换、清理和客户端替换撤销迟到投影；正在写入时不允许移除提示。提示保存、读取或删除失败独立报告本机错误，不修改学校结果；故障时仍不承诺成功持久化，也不降级明文。显式缓存清理/重建会清除提示，确认框说明这一不可恢复范围。学校操作仍沿既有唯一协调器与单次提交合同。


## iOS 私有目录启动边界（P5-B1）

宿主在创建 Core 客户端前初始化私有目录。显式绝对 UBAA_CONFIG_DIR 继续优先；未配置时，iOS 使用原生 FileManager 的 applicationSupportDirectory/UBAA，不依赖 Dart 环境变量中存在 HOME。原生方法只返回本 App 容器路径，不读取目录内容。缺失、相对路径或原生异常使用固定本地错误，不把工作目录、公共临时目录或明文存储作为降级；其它平台原有目录规则不变。并行调用初始化共用同一 Future。账号密钥与缓存载荷的隔离及加密合同保持不变。


## 希冀任务内业务激活复用（P2-S）

每个分段计划只复用自己在原Core客户端完成的业务激活；课程网络读取已经激活时传递该事实，课程来自内存时不能凭缓存授予激活标记。索引/详情每批仍重新选择课程，并在完整读取及会话收尾后释放共享锁。业务认证失效仍执行原有界重新激活与主会话仲裁，失败停止旧计划；账号/路线/客户端代次、取消、清理及写操作保护仍先于后续请求。学校HTTP参数、数据覆盖、TTL和历史复查规则均不改变。


## 首页自动成绩检查的读取优先级（P2-U）

自动成绩检查的学期及成绩需求使用background，首页教学周的共享学期需求使用home，用户打开学期/成绩视图或统计使用interactive。相同账号、生命周期、读取代次和学期的未完成请求共享需求，后来的用户操作可提高下一未发送批次优先级，不能中断已发送HTTP或复制会话。显式成绩视图共享完整学期观察再作本地投影；同页面明确刷新只复用在途观察，不复活已完成的旧结果。其它学期独立，账号/退出/清理/写保护仍先于执行及交付。


## 成绩变化基线统一加密（P4-AH）

课程身份和成绩组成的比较基线属于业务内容，使用Core统一加密库，按账号、实际路线和精确学期隔离。一次完整在线观察经本地通道读取原值并保存新值；空集合、不完整/磁盘来源和学校读取失败不建立或替换基线。密钥、容量、损坏和保存错误独立于学校结果提示，不回退明文、不制造新出分。

平台安全材料能力必须在宿主接线前用专用非敏感键完成写入、读回、删除闭环；只读成功而写入失败时返回不可用句柄，宿主不得构造本地账号仓库。这样在线成绩仍可读取，但不会把后续加密基线写入误报为普通成绩失败，也不会降级明文。退出、重建或清理造成的 `operation_conflict` 属于生命周期取消，不显示为本机保存故障。

旧ui-grade-scores.json只作为迁移输入及显式清理对象，不写入新的成绩。仅在加密保存成功后移除当前账号/路线，已有加密记录优先，其他学期独立迁入；其他账号/路线保留，损坏或迁移期间变化的旧文件不覆盖。退出和清理代次拒绝迟到结果；清理业务缓存也清理该账号遗留基线，成功后撤销内存变化提醒。


## P4-AI：本机账号清理收尾

普通退出保留提醒偏好；“退出并清除”按当前已核实的username/schoolId清理旧成绩与提醒设置，并保留其他账号。宿主本地回调捕获账号生命期，退出、换号或同账号重登后不可再次读写/清除；读取前后检查，已经开始的写入由原串行store在清理前收尾。清理保持原退出保护直到所有本地收尾结束，期间不能新登录。Core清除成功后才移除账号密钥；索引、缓存、会话、凭据及本地偏好任一失败均保留安全诊断并向清除调用方传播，同时尝试其他独立步骤，不宣称完全清除。
