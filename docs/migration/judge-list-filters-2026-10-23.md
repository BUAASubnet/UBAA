# 希冀列表筛选与展示对齐

## 实施前来源核对

基线 `36f04aad`；冻结旧版 `1f4b8f8412272b6a423d4ad92b396e3db721e6f3`，buaa-api `a63712fa2ae0a6c8066197063ddee98e3a6b5b81`，`just refs` 通过。

旧版 `JudgeViewModel.kt` 的 `buildVisibleAssignments`：默认隐藏已截止，仅显示 unsubmitted/partial；课程名与标题忽略大小写搜索；按截止时间升序，可切换开始时间/降序；未知日期不算截止；日期相等以课程名、标题排序；未知时间升序末尾、降序开头。显示已截止会关闭仅未完成，关闭后不自动恢复。`JudgeAssignmentsScreen.kt` 按课程分组；无批量选择入口。摘要隐藏未知状态、缺失时间和零题进度，分数合并展示。

旧版搜索、排序、未完成筛选为本地投影，但 `setShowExpired` 从关闭变为开启时会联网刷新。按用户本轮要求，新版所有展示筛选只作用于已加载数据；需要扩大历史读取范围时使用独立的“加载历史作业”按钮，完成后切换筛选不重读。保留现有显式刷新与渐进读取，不把未加载历史伪装成完整结果。

冻结 buaa-api 没有希冀对应协议或页面实现（仓库检索 Judge/judge/希冀无命中），不借用其他系统字段。此阶段仅修改 UI 投影和入口，CAS/service、跳转/final URL、Cookie作用域、HTTP方法及参数、编码/请求头、加密、DTO解析、缓存/课程串行与错误语义均沿用已核验的[读取修复来源](source-parity-judge-2026-10-23.md)，不修改 Core/Bridge 或内部批量API。

## 实现与覆盖替换

采用 Flutter Material 3 的 ChoiceChip/FilterChip 和已有主题反馈，不引入额外组件库。`JudgeListFilters` 集中管理本地规则，状态随父列表保留；查询面板删除希冀手输编号、批量键和网络筛选草稿，卡片直接进入单项详情。按课程连续滚动，不再套通用的20项分页。

| 删除或替换的旧覆盖 | 保留的行为覆盖 |
| --- | --- |
| UI批量勾选顺序、父页选择保留、混合模型选择入口 | 内部批量API保留；`ubaa_app/test/bridge/forwarding_test.dart`、`dispatch_test.dart` 和 Core `tests/facade/judge_scan/details.rs` 继续验证键传递、逐项保存、失效及错误；UI改为验证跨课程单项打开与返回 |
| 希冀手输详情参数、已加载选择器及失效回填 | 入口删除；单项卡片的typed导航及账号/读取生命周期导航覆盖继续保留 |
| 网络筛选面板的历史/完整刷新和批量键 | 新增本地筛选零查询、显式历史读取一次后反复切换不重读；底层读取刷新覆盖继续保留 |

公共状态和缓存故障测试原来使用缺少作业状态的通用占位，现补齐为未提交作业模型，保留原有失败/陈旧内容与缓存故障断言。
