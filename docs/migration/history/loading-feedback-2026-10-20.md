# 页面加载反馈统一

日期：2026-10-20。基线 `e091ddca`。用户要求首页和其他页面加载时不反复上下跳动，普通加载反馈留在对应内容区。

## 原因与反例

- 连接提示条从主内容上方插入/移除，首页标题纵坐标从 132 变为 72，位移 60 像素。
- 无课日已有空结果刷新时被替换为骨架，待办位置在 298 与 254 之间变化；补充反例失败后改为保留已确认的空状态。
- 同查询刷新已有普通列表时，详情被隐藏为转圈，屏幕内原记录消失；后续结果又恢复列表。
- 全学期成绩异步返回后才插入学期栏，统计卡纵坐标从 92 变为 164，位移 72 像素。

原始三项布局问题以及后续空结果边界均先用合成测试证明失败。修复后的覆盖还包括：首页来源结束时已有待办不移动、刷新按钮原位且不重复发起请求、旧写入按钮原位禁用及新结果返回后恢复。列表测试同时验证滚动偏移保留、换查询的空加载快照不复用旧记录、真实空结果正常显示。

## 统一行为

| 区域 | 处理 |
| --- | --- |
| 全局连接 | 移除改变主内容高度的顶部提示条；连接详情与重试收在工具栏入口，需登录时入口直接完成原位登录。 |
| 首次读取 | 共享详情、课表启动、首页空区域、研讨室时段、图书馆及阳光记录采用内容区静态骨架，不闪烁、不循环列出来源名称。 |
| 主动刷新 | 刷新按钮保持尺寸并显示进度，未结束时禁止重复触发；保留同查询已有详情、概要和滚动位置。 |
| 首页 | 移除待办前的动态加载文字；局部进度在标题固定空间内，错误与重试放到任务之后。 |
| 成绩 | 全学期加载开始即保留学期选择栏位置；同查询刷新继续显示统计和课程。 |
| 研讨室、图书馆 | 刷新期间保留已显示表格/座位和已选区域，只禁用准备预约；不在列表前插入进度条。 |
| 阳光打卡 | 首次记录读取在记录区占位，分页加载进度放在加载更多按钮内。 |
| 门锁、活动类型表单 | 刷新进度放在原按钮中，不增加横向进度条；原密码状态与错误仍按既有生命周期处理。 |

保留缓存时间、不完整范围、错误详情、重试和写入结果不确定信息。学期/教学周选择对话框已有局部加载区域，登录、查询、确认按钮已有按钮内进度；博雅名额与评教进度是业务统计，不作为网络加载条移除。

## 数据与动作边界

仅修改共享 UI 展示及适配该入口的 Host 测试。未修改认证、读取请求/参数、DTO、解析、缓存持久化、并发或任何学校写入协议；两个冻结源仍在登记提交且只读。既有 AppController 只在相同查询时保留快照，换查询发送空加载快照，UI 不另建或复活旧快照。

详情新增写入可用标记，在刷新期间只禁用按钮，保留其布局；原资格判断继续保留。研讨室与图书馆自有流程同步禁用旧选择动作，已打开表单返回时也核对刷新状态和原数据身份。持久缓存仍不授予写入资格。此阶段是用户明确要求的展示调整，不改变冻结源的上游行为合同，不需要真实学校请求来证明布局。

## 验证

- 聚焦布局及研讨室/图书馆/签到/成绩测试：46 项通过。
- 七包完整 Flutter 格式、分析及 1326 项测试通过（UI 341、Host 101、Runner 75，其余包合计 809）；6 张代表性 golden 精确比较通过。
- `just check`、冻结引用、结构、敏感扫描通过。完整检查发现旧测试整理记录中的命令省略了锁文件参数，已补全为与实际门禁一致的写法；重新运行完整门禁通过。
- 空结果边界补充后，`just check-changed` 的 UI/Host/Runner 格式、分析及 517 项测试通过；最终状态矩阵和布局测试再次聚焦验证。macOS Debug 重建成功。
- 沿用原配置目录重启应用，实际进入首页；点击刷新后，已显示课程和待办仍保留原位，只在刷新按钮与待办标题原位显示进度。此观察不代表对所有页面进行真实账号逐按钮验收，也没有提交学校写入。
- 不放宽 golden 比较，不更新像素基准；UI 验收媒体只允许保存到仓库外私有目录，本轮未向仓库写入运行截图。

布局稳定指加载状态本身不插入额外行、不清空已有结果；首次真正返回不同数量的数据，以及用户换查询后的实际内容变化，仍会正常改变内容高度。
