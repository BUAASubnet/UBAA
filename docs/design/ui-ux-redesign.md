# UBAA 全功能 UI/UX 重设计规格

> 用户最新方向已调整：当前优先规格为 [基于旧版界面的多端优化](ui-ux-old-baseline.md)。本文件记录首版方案；四导航、重复常驻工具区等冲突项已失效，未冲突的功能与安全约束继续保留。

日期：2026-09-08。执行合同：`goal.md`。本设计覆盖 `ui-ux-inventory.md` 的 84 个稳定编号，采用 `ui-ux-parity-review.md` 的逐操作 C1–C9 保持条件。本文件是实施规格；原型已由执行代理实际渲染、自评并修正手机首页密度，详见末节。P0 截图是现状资料，不是新设计成果。

## 设计依据与方案裁决

已阅读 `p0-login-macos-dark.png`、`p0-home-macos-dark.png`、`p0-schedule-macos-dark.png`。这组三张 macOS 800×600 深色合成界面显示：登录表单有清晰边界、主色克制；首页卡片层级一致但占用较高，课表筛选横向挤压且周次输入截断；功能详情主要由搜索框、通用卡和大量空白组成。保留蓝色种子、Material 3、明暗层次、熟悉图标和基础操作形态；减少重复标题、强占位卡和技术参数直接输入。截图不证明其他页面或手机/平板运行情况。

| 方案 | 优点 | 代价与结论 |
|---|---|---|
| 保持主页/普通/高级/我的 | 改动少，原导航测试易保持 | 普通/高级不解释学生任务，签到等常用事项被难度标签隔开；不选 |
| 今日/学习/校园/我的 | 按任务找功能；今日可一次进入全部十二领域，分组数量可扫读 | 需迁移目录与名称断言，并保持功能 ID/回调不变；采用 |
| 今日/待办/预约/我的 | 课程作业和预约集中 | 成绩、空教室、统计等被挤入隐性入口；为了归类容易新增业务聚合与请求；不选 |

裁决：四个固定入口为“今日、学习、校园、我的”。学习 7 项＝课表、考试、成绩、空教室、SPOC、希冀、教学评教；校园 5 项＝博雅、图书馆、课堂签到、场馆、阳光。此为导航归类，不改变 FeatureId、网络请求顺序、权限或“高级”能力边界。今日展示十二个直达入口，优先排列今日课程、作业、预约相关入口与已加载摘要；不为仪表盘新增后台预取。任务频率是设计假设，尚无大学生访谈验证。

## 设计变量与组件规范

| 变量 | 规定 |
|---|---|
| 主色 | 保留 `0xFF536AA3`，由 `ColorScheme.fromSeed` 生成明暗色；文本、描边与容器使用语义色，不直接铺大面积主色 |
| 页面底色/卡片 | `surface` 页面、`surfaceContainerLow` 分组；选中用 `secondaryContainer`；边界用 `outlineVariant`；深色仍保留层差 |
| 成功/警告/错误 | 确定成功才用成功标记；未知、未核对、过期使用警示文字及图标；错误用 `errorContainer/onErrorContainer`；不得仅依赖颜色 |
| 字号 | 页标题 24/32，区块 20/28，卡片标题 16/24，正文 14/22，辅助 12/18；按系统字体缩放，1.3 不截主操作 |
| 间距 | 基础 4；字段内部 8，卡内 16，组间 24，页面边距窄 16/中 24/宽 32；宽度紧张时换行而非缩小文字 |
| 圆角/阴影 | 输入与按钮 12，卡片 16，弹层 20；常规卡零 elevation，浮层用 M3 默认；避免所有内容都是同样厚重卡片 |
| 交互区域 | 操作至少 48 逻辑像素；图标必须有标签或 tooltip；焦点 outline 清晰，键盘 Tab 顺序按阅读顺序 |
| 内容宽度 | 内容主体最大 1200，居中；侧栏另占导航宽度；登录表单最大 440；文字详情正文最大 760 |
| 动效 | 120–200ms 淡入/容器变化；不靠动画表达业务提交完成，不重建 client 或重发请求 |

主题为“跟随系统、浅色、深色”，默认跟随系统。偏好保存在 `UbaaAppHost` 当前运行内存：切换页面/账户不重启应用时保持；关闭重开恢复系统，不写 Core 配置 v1、CredentialVault 或新配置文件。个人页明确“本次运行生效”。登录也能使用当前选择的主题；系统模式随平台亮度更新。主题切换不重置导航、查询草稿、写意图或触发业务请求。

## 三端布局与状态连续性

| 可用窗口宽度 | 导航 | 内容与详情 |
|---|---|---|
| 小于 600 | 底部 NavigationBar，四项文字可见 | 单列；筛选折叠面板；详情占当前内容页；卡片操作换行。表单可整页滚动 |
| 600–999 | 80 宽 NavigationRail，选中标签可见 | 内容可两列卡片，但密集详情仍单列；筛选两列弹性布局。不能用平台名称代替实际宽度 |
| 至少 1000 | 200 宽带文字侧栏 | 最大 1200 内容内可列表 360–420 + 详情余宽，或领域表格；有数据且实际可用内容宽度足够才开启双栏 |

验证边界为 599/600/601、999/1000/1001；桌面 800×600 使用中档布局。缩放不创建另一个业务页面状态，导航与内容保持稳定 Widget 身份；用稳定 FeatureId 和选中目标键承载上下文，不能按断点切换两棵丢状态的业务子树。

每领域保存：已应用 `FeatureQuery`、尚未应用的草稿、当前子视图、父列表上下文、本地搜索、滚动偏移、服务端页码、选中详情。返回先退出详情/子选择，恢复父列表；领域返回回到来源分组；再次进入恢复草稿和已应用结果，不自动查询。已应用查询与草稿分开，刷新使用已应用查询。账户变更/退出必须清掉个人数据与全部页面上下文；路线变更保持合法输入但使旧数据明确过期并沿现有 generation 失效规则处理。

手机表单使用 `SafeArea` 与受 `viewInsets.bottom` 影响的可滚动区域；底部“继续确认/确认”不能与键盘重叠。横屏 844×390 和 1.3 字体时筛选允许滚动展开，不把固定高度查询头挤占整个结果区。双栏退回单栏保持同一选中详情；不存在选中项时停在列表。长表只在领域确有必要时横向滚动，并固定或重复课程/日期识别列，不让整页无提示横向漂移。

### 图书馆日期裁决

现有公开 `BridgeLibBookAreaDetail` 含 `availableDates` 与 `timeSlots`，但无日期→时段关联。Core 只解析首项日期时段或顶层回退；不能把时段复制给其他日期。P4前增补核对发现过滤空日期和顶层回退会使首个公开日期与时段来源不一致，现有DTO不能普遍证明首日关联。因此日期和时段分开只读展示，保留原明确输入；新选择器仅在后续公开合同可确认首个可用日期与现有时段对应时开放组合，展示“当前提供首日时段”；slot.id/start/end 原样传为 segment/startTime/endTime。日期为空、时段为空或关联无法确认时保留详情只读，提示“当前数据未提供可确认的日期时段”，不生成预约 target。

其他日期保留既有明确日期/时间查询输入能力与“需核对该日期时段”提示，但不把首日时段设为其他日期默认值，不把无关联结果宣称自动可预约。完整跨日期联动标为阻塞：需要新的来源失败测试及公开合同决策；本轮不改 Bridge v9。父馆、楼层、日期、分区改变即清空旧时段/座位/动作；迟到结果不能恢复旧 action。Core 写入最终预检仍是权威，但不能以“最后会拒绝”代替前端正确提示。

## 所有页面的状态规范

| 状态 | 读取页面 | 写入/设置影响 |
|---|---|---|
| idle/首次加载 | idle 提示开始查询；加载保留标题/筛选，结果区进度，不显示成功勾 | 防重复准备；不禁用无关领域 |
| success | 主内容+更新时间（有值才显示）+实际路线；卡片不重复标题 | allowed+一致 target 才能开启写入 |
| empty | 说明“当前条件暂无结果”，显示已应用条件与调整入口；清掉旧列表 | 不保留旧 action，不猜上游异常 |
| failure | 安全错误、重试、诊断入口；会话失效沿既有恢复流程 | 不能自动切 Demo、自动换路线或重发 |
| stale | 顶部“刷新失败，以下为上次结果”+重试；旧数据可看 | 不把 stale 旧资格当提交权威；prepare 最终重读；需要时提示刷新 |
| 部分失败 | 各领域/各项保留各自结果，不用一个绿勾代表整体 | 评教逐项保持 success/failure/outcomeUnknown/unattempted |
| 长文本/大量数据 | 标题允许换行，详情完整；沿原服务器分页，局部搜索写明当前结果 | 选中项以稳定 target 键保存，结果更新后移除失效项 |
| denied/unknown/能力缺失 | 展示短原因，未知不是拒绝或成功 | 按钮禁用并邻近解释；照片/定位权限失败保留输入，不生成写意图 |

## 写入完整生命周期

`idle → preparing → awaitingConfirmation → committing → verifying → result` 是产品读法，实际状态枚举以现有 `WriteState` 为准，不另建第二状态机。仅共享 `WriteCoordinator` 拥有生命周期。

1. 从领域合法 typed action 开始；字段不足或 target 不一致在准备前拒绝。博雅定位只在 action.requiresCoordinates 为真时获取；阳光照片必须受平台能力门控。
2. 表单呈现人可理解的场地/时段/项目上下文；Cgyy 电话、主题、用途、人数、内容和参与人必填/标志沿现有校验；阳光起止时间、可选地点、照片与公开开关沿现有校验。取消表单不产生业务写入。
3. prepare 完成进入统一确认：目标摘要、真实解析路线、警示、剩余有效时间；显示“确认提交”与“取消”。主题/窗口改变不重新 prepare。
4. 取消调用 discard；取消失败显示可重试错误并保留待确认状态，不能假装已释放意图。过期意图明确失效，不静默重建。
5. commit 仅一次；提交中禁双击、阻止误返回触发重复发送。账户/路线变化、后台恢复与迟到完成按 coordinator 既有失效规则，不能恢复旧意图。
6. 明确成功也需按既定领域读取核对；Cgyy 用订单号及原路线，LibBook 取消回原页，Ygdk 概览+记录，Evaluation 逐目标。收据缺失、回读失败、unknown 或 commit 异常显示“结果待核对”，无自动重试提交按钮。
7. 批量评教单独列每门课程结果；未知导致后续未尝试保持可见，不把整体结束等于全部成功。确认前显示已选数量，确认后结果仍可看，不仅短暂 SnackBar。
8. W-BY-01/02/03/04、W-SIG-01、W-LIB-01/02、W-CG-01/02、W-YG-01、W-EV-01/02 各有独立脱敏实际操作证据。真实业务写入不在本轮范围。
