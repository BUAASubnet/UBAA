# 北航云盘设计与实施安排

日期：2026-10-31。状态：用户已确定完整接入方向，冻结来源已逐操作核对，生产功能尚未实现。

目标：把 bhpan 接入为独立的「北航云盘」功能，Flutter 和 CLI 均可使用，日程同步复用同一套 Core 能力。功能范围覆盖固定 buaa-api Cloud 模块提供的全部操作，按独立可验收的任务逐步交付。

架构：Core 负责认证、路线、文件与分享操作及传输状态。Bridge 只投影稳定类型，平台层提供文件选择和保存能力，App 负责交互编排。日程同步调用 Core 网盘接口，不另行处理 Token、拼接 URL 或维护上传协议。

依据：[日程设计](agenda.md)、[冻结参考](../migration/references.md)、[工程规范](../development/engineering-standards.md)和[开发命令](../development/commands.md)。执行沿用用户确定的分工：主聊天设计、拆分和审查，Codex `gpt-6.1-sol / xhigh` 实现、测试和本地提交。

具体协议与缺口见[来源对照](../migration/source-parity-bhpan.md)，宿主和 Core 的实现边界见[设计合同](../contracts/bhpan.md)。未决协议问题按来源对照逐项处理，源码核对完成不表示真实服务已经验收。

## 范围与来源

固定 buaa-api 的 `src/api/cloud/` 包含 25 个公开业务操作，另有 `login`。下表为接入范围，不是当前实现状态。一个产品操作可以组合多个来源方法；所有方法都需要在来源对照中登记去向。

| 产品能力 | buaa-api 来源方法 | 产品行为 |
|---|---|---|
| 认证 | `login` | 复用学校 SSO，在 Core 内管理网盘会话及失效 |
| 文档库与个人目录 | `get_root_dir`、`get_user_dir` | 浏览账号有权访问的个人、共享、部门和群组文档库 |
| 目录与属性 | `list_dir`、`get_item_size`、`get_suggest_name` | 浏览目录、查看统计、处理名称冲突 |
| 文件管理 | `create_dir`、`rename_item`、`move_item`、`copy_item`、`delete_item` | 建目录、重命名、移动、复制、移入回收站 |
| 回收站 | `list_recycle`、`restore_recycle_item`、`delete_recycle_item` | 查看、恢复、永久删除指定记录 |
| 分享管理 | `share_history`、`share_record`、`share_item`、`share_update`、`share_delete` | 查看、创建、修改、取消分享，支持来源已有的密码、有效期、次数与权限设置 |
| 接收分享 | `share_parse`，结合目录、复制、下载和上传方法 | 打开分享、输入提取密码、浏览下载、另存到个人网盘，向允许上传的分享目录上传 |
| 下载 | `get_download_url`、`get_batch_url` | 下载单个文件、目录打包、多项打包；临时签名地址由 Core 消费 |
| 上传 | `upload_fast_check`、`upload_fast`、`upload_small`、`upload_big` | 秒传检查与提交、普通上传、分片上传，统一显示进度与结果 |

`Root` 的分类只说明文档库读取范围，不提供创建团队或修改组织权限的依据。分享权限中的预览能力也不等于已经具备应用内预览实现。冻结模块没有提供全文检索、在线编辑、版本历史管理或持久断点续传接口，不凭产品名称推断支持。目录内名称筛选可基于已加载列表实现，并明确范围。

旧版应用没有面向用户的网盘页面，但 `buildSrc` 发布工具和测试包含认证、列目录、删除和上传实现。这些操作必须逐项比较；其他操作将旧版列记为不适用。发布脚本只作为代码证据，不运行发布或清理命令。

## 界面与使用流程

「北航云盘」放在「校园」功能页；「我的」中的云盘空间指标提供同一入口。底栏维持日程设计确定的五栏。

- 默认打开个人文档库，提供文档库切换、面包屑、返回上级、刷新和当前目录名称筛选。列表显示名称、类型、大小、修改时间及实际可用状态。
- 新建和上传使用明确按钮。条目菜单提供属性、重命名、移动、复制、下载、分享和删除；多选只编排已有操作，不声称上游具有批量事务。
- 回收站与分享管理使用独立页面。移入回收站与永久删除分别说明结果；分享界面明确可访问内容、提取密码、有效期和权限。
- 传输列表显示排队、正在传输、已完成、失败、已取消或结果待核对。退出或换账号后，旧任务不得继续向新账号提交或刷新列表。
- 文件选择、保存位置和系统打开由平台能力完成；能力缺失时给出具体原因。大文件使用有界缓冲，不把整个文件复制进 Dart 状态或普通 Bridge DTO。
- UI 不展示业务 Token、签名请求头或传输调试数据。用户主动创建或复制的分享链接属于功能输出，不进入自动诊断日志。

## 模块与接口边界

下列为计划落点。具体公开签名在逐操作来源对照后由对应实现任务确定，并与测试一起审查。

| 位置 | 职责与交付边界 |
|---|---|
| `crates/ubaa_core/src/domain/bhpan/` | 文件、目录、分享设置、读取范围、传输状态与稳定错误类型，不含秘密字段 |
| `crates/ubaa_core/src/features/bhpan/` | 分离认证、目录、文件写操作、分享和传输协议，复用现有 transport、路线与会话边界 |
| `crates/ubaa_core/src/facade/bhpan/` | 生产宿主的读取、操作准备、单次提交、传输观察与取消入口 |
| `apps/ubaa_cli/src/command/bhpan.rs` 及执行、输出模块 | `ubaa bhpan` 命令族，支持 human/JSON 与现有 CLI 确认规则 |
| `crates/ubaa_flutter_bridge/src/api/bhpan/` | 类型化读取、操作和传输投影，按合同规则更新版本与生成物 |
| `packages/ubaa_domain`、`packages/ubaa_app` | 展示模型、账号与路线代次、状态恢复和交互编排，复用现有写协调规则 |
| `packages/ubaa_platform`、`packages/ubaa_host` | 文件选择、私有暂存、保存和打开能力，逐平台实现与验证 |
| `packages/ubaa_ui/lib/src/features/bhpan/` | 文档库、目录、详情、分享、回收站和传输页面 |
| Core 日程模块 | 通过网盘 facade 与本地日程存储执行同步合并 |

文件身份、父目录、路线、账号及服务端返回的版本信息在操作期间保持关联。分享目标与个人文档库目标分别建模，Core 持有临时授权上下文。文件名、目录存在和旧缓存均不能证明当前写权限。

CLI 命令包括 `roots`、`list`、`stat`、`mkdir`、`rename`、`move`、`copy`、`delete`、`upload`、`download`，以及 `recycle` 和 `share` 命令组。分享命令覆盖创建、查看、更新、取消、打开与另存。传输输出使用任务标识、进度和安全收据，不把签名 URL 当作普通 JSON 字段暴露。

## 当前必须核实的协议问题

1. **认证与路线。** buaa-api 登录代码留有刷新失效和回调失败的 TODO。逐跳比较两源的 service 编码、相对重定向、最终回调与授权作用域。Cloud 模块没有证明 WebVPN 完整链路，不能据 Direct 路线或通用 URL 包装宣布支持。
2. **同名更新。** 两源上传使用 `ondup = 1`，现有注释将同名视为冲突。尚无条件覆盖证据，返回的 `rev` 不能直接解释为写入前置条件。日程固定文件更新须先解决此问题，不能默认删除旧文件后上传。
3. **多阶段结果。** 普通上传包含开始、对象存储传输和最终登记；分片上传另有分片授权及合并。最终登记前的成功不足以表示文件完成。写请求可能到达服务端后发生超时或解析失败时返回 `OutcomeUnknown`，停止自动重发，先只读核对。
4. **临时地址与授权。** 检验对象存储地址来源、HTTPS、重定向和授权头传播。个人 Bearer 不随意发送给对象存储或其他分享上下文，不同分享授权的文件不能直接拼进同一打包请求。
5. **完整列表与错误处理。** 回收站固定 `start = 0`、`limit = 100`，没有翻页循环。需要证明分页与结束条件，否则报告范围不完整。旧版普通上传的三次 PUT 尝试不得照搬；buaa-api 没有这段业务自动重试。两源日志和错误处理均按 UBAA 脱敏及未知结果规则重写。
6. **参考代码的安全配置。** buaa-api 默认构造器将 `tls = true` 传给 `danger_accept_invalid_certs`，会跳过证书验证；UBAA 必须继续校验 TLS。来源的解析错误会记录原始响应，大文件 PUT 还缺少 HTTP 状态检查。这些行为不能随协议实现复制，分别用错误证书、敏感错误响应和非 2xx 带 ETag 的合成用例约束新实现。

## 执行与验收

当前继续日程明文存储任务，网盘来源审计可同时只读进行。生产代码按依赖顺序安排，避免多个任务同时修改共用 facade、Bridge 版本或生成物。日程 1c、1d 与网盘接入分别提交；日程列表、CLI 和导出不依赖同步完成。

缓存加密不修改。本设计不新增真实账号认证、读取、写入或发布授权；真实测试遵守 [AGENTS](../../AGENTS.md#真实账号与验收范围)。每个协议、存储与跨语言任务先保留失败反例，再完成[完整相关验收](../development/commands.md#检查选择与完成条件)。Flutter、原生和生成命令串行。确定性测试、真实 Direct/WebVPN、平台设备和远端 CI 结果分别报告。
