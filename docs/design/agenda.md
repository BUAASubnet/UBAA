## 目标

把课表、学校待办与用户自建事项放进同一条时间线，统一查看、勾选和安排。学校数据只读，用户的完成、隐藏和备注保存在本地覆盖层，不向学校发起写入。

## 导航

- 底栏改为：首页、学习、日程、校园、我的。「学习」合并原课程与学业的全部功能：课表、签到、SPOC、希冀、博雅、考试、成绩、评教。
- 首页待办的「查看全部」跳转到日程页并带上「待办」筛选，不再原位展开。首页仍显示前四项预览。
- 待办卡片点击后仍打开原功能详情，单层返回。

## 数据模型

所有时间按 `Asia/Shanghai` 本地时间存储，并保留时区标识。

**自建事项**

- `id`：UUID，跨设备稳定。
- `kind`：`event`（有开始与结束，或全天）或 `task`（有截止时间，或无日期）。
- `title`、`location`、`notes`、`color`。
- `start`、`end`、`all_day`、`due`。
- `rrule`：RFC 5545 RRULE 字符串；`exdates`：排除日期。
- `overrides`：单次修改，以原始发生时间（RECURRENCE-ID）为键。
- `completions`：重复待办按发生时间记录完成，不重复的事项只有一条。
- `created_at`、`updated_at`、`deleted_at`（删除标记，供同步合并使用）。

**学校事项覆盖层**

- 键：`来源 + 上游稳定标识`。课程逐节使用 `学期 + 课程代码 + 序号 + 周次 + 星期 + 该节节次`，连堂各节独立覆盖。
- 字段：`completed_at`、`hidden`、`note`、`updated_at`、`deleted_at`。
- 上游状态与本地标记分开显示，本地标记不改变上游结果。用户的本地标记优先决定列表中的完成状态：上游已提交的作业也可以在本地重新挂起，详情仍显示上游状态。

**重复规则**

- Core 引入 `rrule` crate（基于已有的 `chrono`、`chrono-tz`）展开发生时间，引入 `icalendar` crate 导出 .ics。引入前核实版本与许可证。
- 界面提供快捷项：不重复、每天、每周、工作日、按教学周（周范围、单双周、星期）、自定义。教学周与跳过假期按校历换算为 RRULE 加 `exdates`，存储中只有标准规则。
- 修改或删除重复事项时提供三个选项：仅此次（写入 `overrides` 或 `exdates`）、此次及以后（原规则加 `UNTIL`，新建一条）、全部。

## 存储与 CLI

同机同系统用户的 GUI 与命令入口共用原账号别名、缓存密钥和日程库。命令进程结束只释放本进程资源；显式退出、切号和并发恢复由共同服务协调。三平台桌面及 Linux SSH 范围与退役旧 CLI 的顺序见[共享计划](desktop-shared-state.md)。

- 当前实现：自建事项与覆盖层存入 Core 独立的明文 SQLite，事项与覆盖记录各一行，按账号隔离，不随只读缓存淘汰。日程 schema v4 保存逐记录内容、版本、发布序号、启用许可及紧凑删除摘要，已知有效 v2/v3 原子升级并保留原记录，v3 的旧协议在途明确阻断。日程不依赖密钥或整账号密文上限，只写变化行，保留私有路径、事务与退出访问栅栏。其他旧版、未知版和损坏文件拒绝并保留。退出登录或切换账号后不显示，同一账号重新登录即恢复；只有显式清除本机数据时才删除，删除前提示尚未同步的条目。
- facade 暴露查询（按日期范围展开）、增删改、完成、隐藏和导出接口，bridge 做 typed 投影。
- 统一 App 命令提供 `ubaa agenda` 的范围查询、事项增删改、完成、清除及 .ics 导出，支持 human 与 JSON。显式 `agenda sync` 复用 Core 同步服务，具体模型见[日程合同](../contracts/agenda.md#app-日程命令)。
- .ics 当前采用范围快照，每次发生单独导出，保留 Core 展开后的移动、排除及本地完成。非重复事项按 UUID 保持导出身份，重复事项按原始发生键区分。内容行采用线性转义与 UTF-8 折行，输出预算耗尽时整体失败。文件不包含完整重复系列，也没有导入或双向系统日历同步。学校未知时段跳过并报告数量，完整语义见[导出合同](../contracts/agenda.md#rfc-5545-范围快照导出)。

## bhpan 同步

日程同步采用个人云盘中的不可变快照。每台设备只新建自己的文件，不覆盖共同的文件，也不依赖云盘的原子条件覆盖。Core 负责本机事务与记录合并，GUI 和统一 App 命令继续使用同一服务。实现以整合提交 `11832957` 为基线，Direct 完整目录发现与新文件发布使用下述规则，部署验证范围见[当前状态](../migration/status.md)。

### 云端目录与快照

同步目录为 `UBAA/agenda_snapshots`，内部只放文件。文件名为 `p_<设备 UUID 的 32 位小写值>_<20 位十进制发布序号>.json`。设备身份沿用当前账号库的持久 UUID，发布序号与记录编辑序号分别管理。每次发送都新建文件并使用既有 `ondup=1`，不调用覆盖、删除、移动或重命名接口。

快照正文 schema 为 2，包含 `publisher`、`publication`、自建事项、学校事项的本机覆盖和删除摘要。正文身份必须与文件名一致。记录继续按 `(updated_at, device_id, sequence)` 排序；发布序号只用于同一设备的快照选择，不能提高其中记录的版本。完整记录版本相同但内容不同，或者同一发布身份对应不同正文时，整体报错并保留本机数据。正文不含本机 alias、dirty、学号、凭据或学校原始响应。

一次拉取先完整读取同步目录，再为每个设备选择发布序号最大的文件。选择结果全部下载、验证并在内存中合并成功后，才在一个 SQLite 事务内合并到本机。另一设备并发新增的文件可以留到下次拉取；同一设备迟到完成的较小发布序号不会替换较大序号。客户端从不根据文件时间或列表顺序选取“最后一个”。

目录发现保留现有个人库与已签发句柄，在 Core facade 增加[官方分页列举](https://developers.aishutech.com/napi/documents/307)的最小只读实现：`GET /efast/v1/folders/{id}/sub_objects`。首次请求不传 marker，后续原样使用 next_marker，不重新传排序；分页结束后才作缺失或完整判断。Direct 部署已核实全 GNS 百分号编码作为一个路径段，末页 next_marker 为明确空字符串；缺省、null 和短页均不能作为结束。重复 marker、相同 ID 的冲突条目、缺字段、某页失败或取消均使整轮失败，不能交付半份目录。遍历不提供跨时点的服务器快照；只新增不可变文件时，并发较晚出现的文件允许下次从首页发现。

原 `POST dir/list` 的请求不增加分页字段，也不以统计计数代替分页完成证明。中间路径和快照目录使用完成的分页结果定位，缺失才进入原首次确认，存在同名歧义时停止。同步目录内部出现子目录时明确失败，不递归猜测另一套格式。全部分页与所有选定正文核对结束前不改本机数据。

### 本机事务与进程协调

本机日程库一次升级到 schema 4，保留账号别名、设备 UUID、记录编辑序号、全部事项与覆盖记录。同步元数据只增加发布序号、自动同步许可和删除摘要，并扩充原有单条在途记录以保存发布身份及目标文件名。有效 schema 2 可依次执行已有升级和本次升级，事务失败整体回滚。未知、损坏格式继续拒绝。旧单文件协议没有启用过，不读取或迁移云端 `agenda.json`；schema 3 若存在旧协议的在途发送，保留原库并明确阻断，不能把不明写入当作已完成删除。

GUI 与 CLI 在同一账号的同一 SQLite IMMEDIATE 事务中检查原有在途记录、分配发布序号并保存完整发送快照。已有在途记录时只核对，不分配新的发送身份。只有持久保存成功后才能进入上传准备及第一次可能发送的调用。另一进程可核对同一尝试，确认事务只清理仍属于该尝试、且内容和记录版本未改变的条目。账号、路线、关闭或本机清除使旧作用域失效，迟到结果不能确认新的本机状态。

上传前的完整拉取必须包括本设备上次发布的快照。清除本机数据不产生云端删除，不自动启动同步，不发布空快照，也不重置设备身份和发布序号。清除会删除全部事项、覆盖、删除摘要及待发送正文，并使旧作业的作用域失效；若发布可能已经发送，仅保留不含正文的发布身份和已知对象标识，继续占用唯一在途位置。目录创建在途记录随清除释放，原作业仍由生命周期拒绝迟到结果。未决文件发布确认前不分配更高发布序号，不恢复或重放被清除的正文。这样较早发布中尚未可见的删除摘要不会被后来的最高序号永久遮蔽。

无正文的在途限制不阻止本机增删改和其他设备的完整只读合并，旧作业仍不能确认清除后的新状态。没有未决发布时，下一次显式同步或已启用后的新编辑先完整拉取云端，再合并本机新修改；缺失记录不等于删除。未知发布的人工重新发布需要新的明确用户操作，不能由本机清除或后台失败处理自动发起。

### 发布完成与结果未知

上传继续使用现有普通上传、最终登记和当前版本读取 facade。正常路径收到明确成功的最终登记回执后，重新列举目录、取得同名文件的当前 metadata，并读取该当前版本的完整正文。文件身份和正文均与持久发送快照相同时，才清除匹配记录的 dirty 和本次在途记录。开始、PUT 成功、取得 U 或对象可下载均不能代替最终登记成功。

丢失最终回执后，能否仅靠读取自动确认取决于部署的初次文件可见性。如果最终登记前就已能列出同名文件、取得当前 metadata 并读到完整正文，这些读取不足以解除 unknown；该尝试保留 dirty、发布身份和正文，只读核对，不自动重放。这个限制不阻断最终登记明确成功且读回相符的正常路径，也不能用延时补成完成证明。

最终登记明确成功后，在原在途记录持久保存成功回执及对象、版本、名称、大小。后续读回中断或进程重启时，只继续核对原发布的当前 metadata 与完整正文；全部一致后才确认本机发送。未取得明确回执的发布持续保持结果未知。结果未知时，不重传同名文件，不自动换名重传，不删除远端目标；未发现目标或正文不匹配均不足以证明原写入未发生。用户明确发起“重新发布新快照”应作为独立的新操作设计，不能由失败处理自动触发。其他设备已明确发布的快照仍可读取，本设备未知发布保持冻结。

### 删除、恢复与保留

每个删除摘要只含事项 UUID 或覆盖键、删除时间及原记录版本，不含标题、备注、重复规则或学校正文。新快照中的删除记录只发布该摘要。本机保留摘要，即使完整的已同步删除记录超过 180 天被清理，之后读到的旧版本也不能复活记录。所有设备选择的最新快照必须携带各自已知摘要。摘要和普通记录仍按原记录版本比较；旧设备提高发布序号不会提高旧记录版本。事项恢复使用新 UUID；学校覆盖明确重新设置时可以产生更高版本的覆盖，保持原有交互语义。

180 天规则继续只清理已经同步的本机完整删除记录。未同步删除不能清理，必要的紧凑摘要持续保留；显式清除本机数据仍清除本机摘要，后续同步先从云端恢复摘要。首次发现的删除摘要和旧记录必须一起完成目录读取及合并，不能先展示旧记录再等另一份文件删除它。

本次不自动清理云端旧快照。这避免为并发发布增加云端删除，也意味着早期快照可能仍保留历史标题与备注，云端存储会增长。180 天是本机记录清理规则，不承诺删除云端历史。单份与合并正文继续使用既有容量上限；超限保留本机状态并明确失败，不静默遗漏文件或删除记录。

### 启用与本机离线行为

现有 CLI 本机查询、创建、编辑、删除、清除与导出直接调用本机日程句柄，继续零学校请求；只有显式 `agenda sync` 进入云端。账号库增加明确的自动同步许可，默认关闭，schema 3 升级也保持关闭。GUI 打开日程页和未启用时的本机保存只更新本机数量，不登录、查目录或上传。

GUI 的“启用云端同步”沿用首次创建确认流程，确认同一账号与路线后才保存许可并执行作业。显式只读拉取不自动打开许可；CLI 的单次 `--confirm-write` 也不改变 GUI 自动同步设置，`--create --confirm-write` 对应明确启用。许可打开后，GUI 每次进入拉取一次、本机编辑后发送一次；失败不安排后台重试。本机清除不触发发送，账号切换读取各自许可。界面展示“仅保存在本机”“等待同步”“云端读取未完成”“结果待核对”等状态，不展示 schema、设备序号或内部协议名。

### 失败反例与验收

1. 两设备基于相同旧状态同时发布不同记录，云端保留两个文件，下一轮双方包含并集；同一记录不同版本仍按原排序收敛。
2. 同机两个独立进程同时发送，只分配一个在途发布身份；保存失败零请求；崩溃后只核对原文件，不换名重传。
3. 较小发布序号迟到完成、列表倒序或重复返回，均不覆盖本设备较新快照；相同发布身份的不同正文明确失败。
4. 多页出现重复 marker、缺少结束依据、漏页、失败或子目录时，不合并、不发布空状态、不清 dirty；下次从首页完整读取才继续。
5. 最终登记明确成功且当前文件与正文相符时确认。开始或 PUT 后、最终登记前的可见性不能代替成功回执；如果该阶段已满足全部读取条件，丢失最终回执后仍保留 unknown、dirty 和原发布身份。明确成功后的读回中断只继续核对，不重新发送。
6. 180 天清理后，旧设备后来发布的旧记录不能越过删除摘要；覆盖明确重设仍可产生新版本；删除摘要序列化不带标题或备注。
7. 用 barrier 固定交错：p6 含 Xv1，p7 含删除摘要 v2 且最终登记挂起，清除本机后仅能发现 p6。此时允许创建 Y 和合并其他设备，但拒绝分配或发送 p8；p7 晚到也不能确认清除后的状态。重开后仍保留无正文的 p7 在途身份，正文和摘要均已擦除，不自动恢复或重放。
8. 未启用 GUI、本机 CLI 以及显式只读拉取后的本机保存，认证、目录与上传调用数均为零；只有确认后的 GUI 自动作业和显式同步命令进入云端。

- 顶部：教学周与七日日期条，左右滑切周，有事项的日期带圆点；右上角切换列表、周、月，带搜索。
- 筛选：全部、课程、作业、博雅、考试、研讨室、我的；可隐藏已完成。
- 分组：逾期（可折叠，红色）置顶，随后按天分组。每天依次为全天事项、按开始时间排序的时段与截止事项。课程逐节显示。
- 条目：左侧色条表示来源，标题，副标题为来源与地点；截止事项显示倒计时；可勾选的条目右侧有复选框。左滑完成或隐藏，长按打开菜单。
- 冲突：自建或预约事项与课程重叠时，副标题提示冲突。

**周视图**：与课表共用七日网格和固定时间轴，按北京时间显示 00:00—24:00。课程、预约和自建时段使用 Core 已展开的发生记录，重叠时并排显示，跨午夜事项在相邻日期各显示对应部分。全天、截止、无日期和时间待确认事项位于顶部条带。窄屏初始显示焦点日期，可以横向滚动，时间轴固定在左侧；普通刷新保留手动滚动位置。

**月视图**：月历按周一到周日排列六行日期，有符合筛选条件事项的日期显示圆点。点击日期后，下方显示当天事项，跨日事项按实际覆盖日期显示，全天结束日期不包含在范围内。无日期待办独立保留。月底前后导航落在目标月的有效日期。

**日期与筛选**：列表、周、月共用焦点日期、搜索、来源和完成/隐藏筛选。列表保留原先的默认日期范围（焦点日期前七日至后三十一日，结束日期不包含在内），日期条或月历选日后可以只看当天，再选择“显示全部日期”恢复范围列表。周视图显示焦点所在的周，月视图显示焦点所在的月。左右按钮和 `Alt+←/→` 按当前视图切换周或月，“今天”回到当前校园日期。搜索与备注输入中保留平台文字编辑快捷键。翻周保留当前的全范围或单日筛选，只有主动选日才进入当天列表。列表仍可选择自定义日期范围。

**详情**：学校事项显示来源信息与「打开原功能」，可加本地备注、标记完成或隐藏；自建事项可编辑、删除。

**新建**：列表顶部“新建事项”打开编辑页，选择日程或待办，填写标题、全天、时间或截止、重复、跳过假期、地点、颜色、备注。时间按北京时间输入，全天结束日期不包含在事项内。

**冲突提示**：自建事项保存前，将当前编辑发生与对应日期的已缓存课程比较。发生重叠时列出课程和时间，由用户返回修改或继续保存。列表、周视图和详情同时提示自建事项或已有预约与课程的重叠，筛选或隐藏课程不取消冲突依据。结束与另一事项开始相接不算重叠。课程或预约只有日期占位、尚未确定时段时，不将占位当作全天冲突依据。重复系列在已加载范围内使用 Core 的每次发生逐一展示冲突，不在界面重新展开 RRULE，也不修改学校数据。

**宽屏**：左侧月历与筛选，中间为当前视图；空间足够时右侧显示详情栏。详情栏与窄屏面板共用完成、编辑、删除、隐藏、备注及原功能导航。详情按稳定事项/发生身份选择，刷新后更新内容，账号或路线变化时清除旧详情。列布局按可用宽度和字体大小决定，窄窗口仍使用完整的单列操作。

## 分期

列表、详情、新建编辑、完成/隐藏/备注和 `.ics` 导出已完成本地交付。后续继续复用相同 Core 和日程服务。

周/月视图、冲突提示和宽屏布局已通过独立复审并进入整合分支。App 命令与 bhpan 继续分别推进，日程同步依赖网盘所需的读写与并发证据。本地通知、自然语言添加和系统日历双向同步不在本次范围。

## 当前交付的验收场景

| 场景 | 用户可观察的结果 |
|---|---|
| 查看汇总 | 日程默认列表按天展示学校事项和自建事项，支持既定来源筛选；空数据、缓存缺失和读取失败有明确状态 |
| 导航 | 底栏采用首页、学习、日程、校园、我的；首页“查看全部”打开日程待办筛选，学校条目可返回原功能详情 |
| 编辑自己的事项 | 新建日程/待办，修改或删除，处理仅此次、此次及以后、全部三种重复范围；重开页面后数据保持 |
| 管理本地标记 | 完成、重新挂起、隐藏和备注可保存，学校原始状态仍可查看，本地操作不发送学校写请求 |
| 离线使用 | 本机事项可读写，学校事项使用现有缓存并显示范围与更新时间；没有缓存时仍可操作自建事项 |
| 导出文件 | 选择日期范围，沿用 Core 快照语义保存 `.ics`；取消、权限拒绝或保存失败给出准确结果，不误报成功 |
| 账号与路线变化 | 退出或切号后旧数据立即停止展示；同账号重新登录恢复本机日程；路线切换不混入旧路线学校结果 |

## 实现与验证边界

日程操作复用 `packages/ubaa_app` 的独立日程服务和 `bridge/agenda` 适配，UI 位于 `packages/ubaa_ui`，导航和平台能力由 `packages/ubaa_host` 接线。Core 继续拥有重复展开、学校来源合并和导出序列化；文件选择与保存由平台能力负责，先选择位置再核对作用域并提交内容，实际写入完成后才报告保存结果。平台行为及写入边界见[文件保存说明](../../packages/ubaa_platform/README.md#日历文件保存)。

每次从首页“查看全部”进入日程都会重新启用待办筛选，其余筛选和页面位置继续保留。编辑重复系列时，未修改的跳过日期交由 Core 随系列平移或拆分；用户明确修改跳过日期时，内容、重复规则和排除日期一起保存。

学校缓存按来源分别展示保存与核验时间，并可展开查看各查询范围。核验超过五分钟、最近更新失败、部分结果和最近更新尚未核验分别提示，保留已有缓存事项。所有时间统一使用北京时间。缺少学校学期信息时，导出面板明确提示仅导出本机事项；存在学期信息时，缓存损坏或身份错误继续使导出失败。

保留 `packages/ubaa_app/test/agenda` 的生命周期与 Bridge 覆盖，以及 App/Host 的首页投影和路线测试。新测试围绕列表、编辑持久化、导航和文件交付的实际行为。按[开发命令](../development/commands.md#检查选择与完成条件)执行聚焦及相关检查，平台实际运行范围单独记载。

账号、存储或跨语言缺陷只在实际影响本次流程时纳入当前修复。未合并共享候选的三个阻塞继续登记于状态页，采用候选实现前必须解决。当前计划不要求增加新的账号体系或重新划分 Dart 包。
