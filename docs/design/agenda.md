# 日程

更新：2026-11-04。当前产品目标是交付日程界面。Core 自建事项、重复规则、学校投影、本地合并查询、独立 Bridge/Dart 服务、首页七类待办统一投影和 Core 范围快照 `.ics` 导出已在主线。Flutter 日程入口、编辑交互和导出文件仍待接通。具体候选与验证见[当前状态](../migration/status.md)。

既定需求保留：课程逐节显示；完整重复规则；课程与学业合并为「学习」；中间一栏为日程；本机日程使用逐记录明文 SQLite，业务缓存继续加密。App 命令读写日程、bhpan 明文 JSON 同步作为后续交付，修改后同步、失败不自动重试的规则保持。本地通知不在当前范围。

## 目标

把课表、学校待办与用户自建事项放进同一条时间线，统一查看、勾选和安排。学校数据只读，用户的完成、隐藏和备注保存在本地覆盖层，不向学校发起写入。

## 导航

- 底栏改为：首页、学习、日程、校园、我的。「学习」合并原课程与学业的全部功能：课表、签到、SPOC、希冀、博雅、考试、成绩、评教。
- 首页待办的「查看全部」跳转到日程页并带上「待办」筛选，不再原位展开。首页仍显示前四项预览。
- 待办卡片点击后仍打开原功能详情，单层返回。

## 事项来源

| 来源 | 形态 | 时间字段 | 完成状态 |
|---|---|---|---|
| 课表 | 时段 | 节次时间（按校历） | 无 |
| 考试 | 时段 | 考试日期与起止时间 | 无 |
| 博雅 | 时段 | 课程起止时间 | 上游签到状态 |
| 研讨室预约 | 时段 | 预约时段 | 上游订单状态 |
| SPOC 作业、希冀 | 截止 | 截止时间 | 上游提交状态 + 本地标记 |
| 签到 | 时段 | 今日课程起止时间，沿用首页排序和签到提醒窗口 | 上游状态 |
| 阳光打卡提醒 | 截止 | 本周日 23:59:59 | 上游统计与本地提醒设置 |
| 用户自建 | 时段、截止或全天 | 用户填写 | 本地 |

学校来源的投影规则沿用现有首页待办，迁入 Core 后由 Flutter 与 CLI 共用。课表后续周依赖整学期导入（`CachedSemesterSchedule`）。未导入时只显示已读取的周，并提示导入整学期课表。

## 数据模型

所有时间按 `Asia/Shanghai` 本地时间存储，并保留时区标识。

**自建事项**

- `id`：UUID，跨设备稳定。
- `kind`：`event`（有开始与结束，或全天）或 `task`（有截止时间，或无日期）。
- `title`、`location`、`notes`、`color`。
- `start`、`end`、`all_day`、`due`。
- `rrule`：RFC 5545 RRULE 字符串；`exdates`：排除日期。
- `overrides`：单次修改，以原始发生时间（RECURRENCE-ID）为键。
- `completions`：重复待办按发生时间记录完成，不重复的事项只有一条。
- `created_at`、`updated_at`、`deleted_at`（删除标记，供同步合并使用）。

**学校事项覆盖层**

- 键：`来源 + 上游稳定标识`。课程逐节使用 `学期 + 课程代码 + 序号 + 周次 + 星期 + 该节节次`，连堂各节独立覆盖。
- 字段：`completed_at`、`hidden`、`note`、`updated_at`、`deleted_at`。
- 上游状态与本地标记分开显示，本地标记不改变上游结果。用户的本地标记优先决定列表中的完成状态：上游已提交的作业也可以在本地重新挂起，详情仍显示上游状态。

**重复规则**

- Core 引入 `rrule` crate（基于已有的 `chrono`、`chrono-tz`）展开发生时间，引入 `icalendar` crate 导出 .ics。引入前核实版本与许可证。
- 界面提供快捷项：不重复、每天、每周、工作日、按教学周（周范围、单双周、星期）、自定义。教学周与跳过假期按校历换算为 RRULE 加 `exdates`，存储中只有标准规则。
- 修改或删除重复事项时提供三个选项：仅此次（写入 `overrides` 或 `exdates`）、此次及以后（原规则加 `UNTIL`，新建一条）、全部。

## 存储与 CLI

同机同系统用户的 GUI 与命令入口共用原账号别名、缓存密钥和日程库。命令进程结束只释放本进程资源；显式退出、切号和并发恢复由共同服务协调。三平台桌面及 Linux SSH 范围与退役旧 CLI 的顺序见[共享计划](desktop-shared-state.md)。

- 当前实现：自建事项与覆盖层存入 Core 独立的明文 SQLite，事项与覆盖记录各一行，按账号隔离，不随只读缓存淘汰。日程 schema v2 已移除密钥依赖和整账号密文上限，仅写入变化记录，保留私有路径、事务与退出访问栅栏。旧版或未知文件直接拒绝并保留，不自动迁移。退出登录或切换账号后不显示，同一账号重新登录即恢复；只有显式清除本机数据时才删除，删除前提示尚未同步的条目。
- facade 暴露查询（按日期范围展开）、增删改、完成、隐藏和导出接口，bridge 做 typed 投影。
- CLI 计划提供 `ubaa agenda` 子命令：列出指定范围、增删改自建事项、完成及导出 .ics，支持 human 与 JSON。旧独立入口已接入 list/show/unsynced，后续将迁到 App 命令模式并补齐修改与导出；具体模型见[日程合同](../contracts/agenda.md#app-日程命令)。同步接通前不提供成功的 sync 命令。
- .ics 当前采用范围快照，每次发生单独导出，保留 Core 展开后的移动、排除及本地完成。非重复事项按 UUID 保持导出身份，重复事项按原始发生键区分。内容行采用线性转义与 UTF-8 折行，输出预算耗尽时整体失败。文件不包含完整重复系列，也没有导入或双向系统日历同步。学校未知时段跳过并报告数量，完整语义见[导出合同](../contracts/agenda.md#rfc-5545-范围快照导出)。

## bhpan 同步

日程同步规划复用[独立 bhpan 网盘 Core](bhpan.md)的登录、目录与文件读写能力，不在日程模块维护第二套网盘协议。目前已有本机存储与范围快照导出，同步协调和网盘接线仍未实施。

- 文件：用户个人目录下的 `UBAA/agenda.json`，明文 JSON，包含 `schema` 版本、自建事项与覆盖层，不写入学号或凭据。
- 拉取：打开日程页时下载一次，与本地逐条合并。
- 合并：按记录 `id` 比较 `updated_at`，较新者胜；时间相同按设备标识决定。未同步删除标记一律保留，仅清理已同步且严格超过 180 天的删除标记。
- 上传：本地修改后上传一次。失败或结果不确定时标记「待同步」，不自动重试；结果不确定时先读回远端再决定。上传完成后读回核对。
- 网盘协议由独立 bhpan Core 负责，来源对照、认证与各操作边界见[网盘设计](bhpan.md)。日程同步只使用其公开 facade，不自行推断 URL、字段或重试规则。
- 待核实：上传是否支持条件写入（防止两台设备同时覆盖）；WebVPN 路线能否访问 bhpan；token 有效期与刷新方式。真实账号验证需单独授权，Direct 与 WebVPN 分别登记。

## 界面

**列表视图（默认）**

- 顶部：教学周与七日日期条，左右滑切周，有事项的日期带圆点；右上角切换列表、周、月，带搜索。
- 筛选：全部、课程、作业、博雅、考试、研讨室、我的；可隐藏已完成。
- 分组：逾期（可折叠，红色）置顶，随后按天分组。每天依次为全天事项、按开始时间排序的时段与截止事项。课程逐节显示。
- 条目：左侧色条表示来源，标题，副标题为来源与地点；截止事项显示倒计时；可勾选的条目右侧有复选框。左滑完成或隐藏，长按打开菜单。
- 冲突：自建或预约事项与课程重叠时，副标题提示冲突。

**周视图**：复用课表七日网格，叠加自建时段事项；截止事项显示在顶部条带。

**月视图**：月历加圆点，下方显示选中日期的列表。

**详情**：学校事项显示来源信息与「打开原功能」，可加本地备注、标记完成或隐藏；自建事项可编辑、删除。

**新建**：右下角「+」打开面板，选择日程或待办，填写标题、全天、时间或截止、重复、跳过假期、地点、颜色、备注，保存前提示与课程的冲突。

**宽屏**：左侧月历与筛选，右侧列表；更宽时右侧再分出详情栏。

## 分期

当前交付为 Flutter 导航调整、列表视图、详情、新建与编辑、完成/隐藏/备注，以及 `.ics` 文件导出。复用已有 Core 和日程服务，不等待三平台命令入口或旧 CLI 退役。

后续分别交付 App 日程命令、bhpan 同步，以及周/月视图、冲突提示和宽屏布局。同步依赖网盘所需的读写与并发证据，视图完善可独立推进。本地通知和自然语言快速添加继续保留为后续功能。

## 当前交付的验收场景

| 场景 | 用户可观察的结果 |
|---|---|
| 查看汇总 | 日程默认列表按天展示学校事项和自建事项，支持既定来源筛选；空数据、缓存缺失和读取失败有明确状态 |
| 导航 | 底栏采用首页、学习、日程、校园、我的；首页“查看全部”打开日程待办筛选，学校条目可返回原功能详情 |
| 编辑自己的事项 | 新建日程/待办，修改或删除，处理仅此次、此次及以后、全部三种重复范围；重开页面后数据保持 |
| 管理本地标记 | 完成、重新挂起、隐藏和备注可保存，学校原始状态仍可查看，本地操作不发送学校写请求 |
| 离线使用 | 本机事项可读写，学校事项使用现有缓存并显示范围与更新时间；没有缓存时仍可操作自建事项 |
| 导出文件 | 选择日期范围，沿用 Core 快照语义保存 `.ics`；取消、权限拒绝或保存失败给出准确结果，不误报成功 |
| 账号与路线变化 | 退出或切号后旧数据立即停止展示；同账号重新登录恢复本机日程；路线切换不混入旧路线学校结果 |

## 实现与验证边界

日程操作复用 `packages/ubaa_app` 的独立日程服务和 `bridge/agenda` 适配，UI 位于 `packages/ubaa_ui`，导航和平台能力由 `packages/ubaa_host` 接线。Core 继续拥有重复展开、学校来源合并和导出序列化；文件选择与保存沿用平台能力，不在 UI 重写业务规则。

保留 `packages/ubaa_app/test/agenda` 的生命周期与 Bridge 覆盖，以及 App/Host 的首页投影和路线测试。新测试围绕列表、编辑持久化、导航和文件交付的实际行为。按[开发命令](../development/commands.md#检查选择与完成条件)执行聚焦及相关检查，平台实际运行范围单独记载。

账号、存储或跨语言缺陷只在实际影响本次流程时纳入当前修复。未合并共享候选的三个阻塞继续登记于状态页，采用候选实现前必须解决。当前计划不要求增加新的账号体系或重新划分 Dart 包。
