# 可维护性治理设计

日期：2026-09-07。基线：`95705fdcf1095ad42d1c85b25e208ca302263a0f`。
用户已授权制定计划并完成修复，本设计和实施连续执行。

## 目标和范围

关闭本轮审查的错误语义损失、诊断信息缺失、重复错误策略和交接证据不可移植问题；补充生产传输与原生产物检查，保证维护者能从错误定位到操作、阶段和源码责任边界。

采用现有架构内的渐进治理。仅补文档不能关闭实际错误传播问题；全仓重写会增加协议和并发回归风险，因此不采用。领域分工、Core facade、单一 WriteCoordinator、原路线回读继续作为权威。

## 安全和兼容约束

- 冻结引用、凭据、真实会话和原始响应只读；保持当前暂停真实 App/Core-live 的约束。
- 不执行业务写入、签名发布、安装设备或上传诊断，不自动重试上游请求。
- CLI schema v10、FRB bridge v9、Session v2、config v1 保持；本次不增加 wire 字段或更改上游请求和公开 Rust 错误。
- Rust 诊断只是私有分类和 tracing，不能暴露 URL、正文、完整原因字符串、Cookie 或个人数据。
- Dart 错误修复采用已有 Bridge 字段；新增字段为宿主内部模型的可选字段，保留旧构造器和公开便捷入口。
- 本机脱敏诊断默认仅在内存中有界保存，用户主动查看/复制；不写磁盘、不自动上传、不影响业务成败。
- 不以通用重试标志触发写入重放。结果未知始终要求核对，保留原有状态机与回读规则。

## 1. 单一错误策略和完整传播

由现有 platform `UiErrorMapper` 拥有展示模板和恢复默认值；app `UbaaErrorMapper` 保留兼容入口并委托该实现。

domain 定义可共享的错误类别，UiError 和 BackendException 增加可选类别、retryable、resolvedRoute 元数据。BridgeBackend 对 typed BridgeError 使用穷尽枚举映射，登录逐路线 SafeError 使用独立字符串适配并保留实际失败路线。异常转 UI 不再只传 code；parseError 不改变为 upstreamChanged。保持 Core 的 retryable=false，包括上传等不可重复操作。

新增跨 BridgeBackend、AppController、协调器的失败传播测试，验证具体字段、用户恢复动作和失败路线，确保文案共享不损失代码。兼容旧入口的同时消除重复模板和字符串映射的静默缺口。

## 2. 本地可追溯诊断

platform 提供有界内存诊断记录器，字段仅接受受控操作、错误类别/代码、路线、领域、耗时、异常类型分类和经过白名单筛选的项目源码位置。产生每次运行内唯一的关联编号，绝不调用原始异常的 toString。

AppController 在初始化、认证、路由、读取及生命周期兜底记录失败；WriteCoordinator 的 prepare/commit/discard 和回读错误使用同一记录器。仅记录当前代次结果，旧会话完成不得写入当前 UI。遥测和诊断失败不能把成功业务改为失败，必须隔离并测试。

错误卡显示可复制的安全错误编号和机器码；个人页提供本次运行的诊断查看/复制入口。默认不上传，记录不含账号或业务输入。保护已有空态、旧数据和结果未知语义。

Rust 传输在请求发送/响应读取失败时记录阶段、保守原因分类和耗时，不改对外 UbaaError。分类只依据 reqwest 的稳定判断和有限错误链中的 std::io::ErrorKind；无法确认的 TLS/DNS 等原因保持未知，不能检查原始错误字符串猜测。

## 3. 确定性工程门禁

完善 macOS 产物检查：在已有包上读取实际签名权限，断言 Sandbox 和 network.client，不能只看源码 entitlement；加入移除权限会失败的隔离回归。不访问学校。

保留通用 just check 的可用性，但提供要求 ShellCheck 存在的严格入口，并接入完整维护验收，文档明确两者区别。本机使用固定校验过的 ShellCheck 执行最终严格门禁。

生产 Reqwest 的本地回环服务测试覆盖真实 GET/POST、状态/响应读取、连接失败和已有大小预算；不以 Mock 成功代替具体适配器接线。

## 4. 文档与证据

归档原 macOS 活动合同及旧 status 全文，goal.md 切换到本轮治理，保留真实测试暂停状态。当前状态只列当前事实和剩余产品验收边界。

增加仓库内脱敏历史证据摘要，链接公开 CI run 并记录其已验证源码 SHA、历史日期和证据限制，不要求其它维护者访问个人绝对路径。当前源码验证与随后文档记录分别标识，文档更新不伪称新增源码验证。

补充错误排障手册、定位索引和 source-parity 记录。已知暂不可用的原生能力和真实验收不伪装成已完成。

## 完成标准

1. 每个行为修复先有预期失败证据，再有通过证据；无新增敏感信息输出。
2. 错误字段跨层保留，单一模板；未知异常可关联到安全诊断，遥测/诊断不改变业务结果。
3. 传输和 macOS 实际产物门禁可发现对应回归。
4. refs、零例外 layout、敏感扫描、严格 Rust/Shell、CLI、完整 Flutter、FRB 零漂移、可用的 macOS 构建/产物/integration 门禁通过。
5. 独立审查无未处理高、中风险问题，阶段提交干净；明确其它平台与真实系统未重验的范围，不声称抽象意义上的满分或正式发布。
